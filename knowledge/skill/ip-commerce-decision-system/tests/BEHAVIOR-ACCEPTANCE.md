# 决策行为语义验收

结构回归只证明规则、Skill、字段和案例文件存在，不能证明模型在真实问题中会正确执行。语义验收只观察最小决策记录，不索取或保存隐藏思维。

## 四层验收

1. **结构回归**：每次相关变更必跑 `Test-DeepReasoningStructure.ps1`，验证活动入口、三检查点、路由、锚点与案例结构。
2. **审计案例**：规则变更或定期审计时先跑 `Test-DecisionAuditFixtures.ps1` 检查测试合同，再用 `deep-reasoning-behavior-cases.json` 和 `decision-audit-fixtures.json` 对可观察记录做语义评审。
3. **跨模型交叉评审**：只在当前用户明确授权后运行。默认使用合成或脱敏案例；含私人知识、对外发送或产生费用时必须再次取得当前授权。
4. **真实结果验收**：随真实任务发生，记录动作、结果和用户批准/否决；只有用户批准或真实结果能晋升方法。

单一模型不得自评“语义合格”。多模型意见不投票；出现分歧交给人工复核。跨模型未运行时必须明确写“未运行/未认证”，不得用结构测试的通过数冒充行为通过数。

## 审计模式对 IP-005 的边界

- 只能由明确测试或审计请求触发；
- 只输出 `decision-audit-record.schema.json` 允许的可观察字段；
- 不输出隐藏推理；
- 不泄漏进普通回答，测试结束即恢复自然表达；
- 测试结果不能自动晋升规则。
