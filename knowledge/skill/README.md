# 活动 Skill 总目录

本知识库保留七个面向用户的主入口。蒸馏与知识库维护分开，避免“学习内容”和“维护文件系统”混在一起：

只有下表七个顶层目录中的 `SKILL.md` 会被注册。主 Skill 内的 `modules/*/RUNBOOK.md` 是按需读取的内部执行手册，不是独立 Skill，也不能用旧名称直接触发。

| Skill | 负责什么 | 不负责什么 |
|---|---|---|
| `knowledge-distillation` | 视频/PDF/文档完整文字化、资料蒸馏、个人技能蒸馏、Skill 生成与迭代 | 知识库搬家、普通盘点、会话交接 |
| `knowledge-iteration` | 来源登记、知识库维护、复盘、会话交接、归档、manifest 与迁移 | 资料或个人技能的具体蒸馏 |
| `tiktok-commerce-operations` | 选品、SKU、店小秘、定价、活动、飞书、Listing、投流数据诊断 | 视频生产、达人发送 |
| `tiktok-content-system` | 涨粉、爆款仿写、投流素材、文案、HeyGen、B-roll、ChatCut | 商品价格和店铺派工 |
| `tiktok-creator-outreach` | 达人导表、评分、深审、未发送草稿、结果复盘 | 未经授权实际发送 |
| `ip-commerce-decision-system` | 个人 IP、带货策略、蒸馏经验驱动的决策 | 外部实时数据抓取 |
| `linkfox-research` | 跨境平台外部数据和研究证据 | 替用户做最终业务决定 |

以后直接描述目标即可，不需要记旧 Skill 名称。需要强制指定时可写 `$skill-name`。

所有入口共同遵守 [规则权威与变更协议](../资产/规则/规则权威与变更协议.md) 和 [活动规则总表](../资产/规则/活动规则总表.md)。旧对话、附件、归档和 AI 自拟内容不自动生效。

七个入口都保持自动发现。每个 Skill 在确认任务模式后，会按 [蒸馏知识自动调用与 Skill 同步协议](../资产/规则/蒸馏知识自动调用与Skill同步协议.md) 主动读取相关活动方法；用户不必另外说“调用知识库”。跨 Skill 的执行顺序和 TikTok 新方法分配见 [七个主 Skill 自动运营总图](../资产/规则/七个主Skill自动运营总图.md)。

自动调用以用户当前具体问题为起点：先识别对象、阶段、证据与瓶颈，再只选适用方法给出针对性判断和执行，不把知识库当成通用资料清单输出，也不要求用户再次提醒。
