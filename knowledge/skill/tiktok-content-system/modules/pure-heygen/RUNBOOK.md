# 内部执行手册：纯 HeyGen 数字人口播

> 本文件不是独立 Skill。只有 `tiktok-content-system` 路由到 `pure_heygen` 时才读取。旧 `heygen-video-producer` 名称和旧电脑路径不再作为入口。

## 锁定定义

用户说“做数字人口播”或“纯数字人口播”时，默认生成稳定 9:16 HeyGen 人物口播，不自动增加 B-roll，也不自动进入 ChatCut 混剪。

## 路径与状态

1. 先运行本模块 `scripts/workspace_state.py recover`；用户给出任务目录时传 `--task-dir`，否则让脚本按进行中项目摘要和 `productionWorkRoot` 内的 `ACTIVE_TASK.json` 恢复。
2. 只有精确任务目录或唯一可证明的近似目录可以采用；发现多个候选时才列出差异让用户选择。不得创建一个下划线、空格或日期略有不同的近重复任务树。
3. 路径未配置时停止写入，不回退到旧盘符、旧知识库或 Skill 目录。当前机器的默认生产根来自 `machine-paths.local.json`，不能仅从对话猜测。
4. 以任务目录中的执行表、文件和 `ACTIVE_TASK.json` 为运行状态源；以知识库项目摘要补充业务状态和批准记录；聊天记录只用于追溯，不是运行状态。
5. 读取 `references/validated-production-baseline.md` 和 `vault_root/资产/规则/最新批量批准标准索引.md`。样片批准只允许通过样片门；只有项目记录了用户明确批量批准，才按最新标准继续剩余清单。

## 自动衔接与前置检查

先把当前 SKU 分为以下分支，不把内部路线选择问给用户：

1. **缺真实商品图或店铺/SKU事实**：列出精确缺口并停止该 SKU，不生成外观。
2. **商品与事实齐全，但人物图缺失**：自动调用同一 `tiktok-content-system` 的 `content_preparation`，依据 SKU、受众和使用场景生成一个人物候选；随后锁定真实商品源层并做人物、手部、包装与真实感质检。
3. **人物图存在但未通过当前基准**：修复或重做一张候选，不进入 HeyGen；禁止用空手图、通用人物或模型重画商品临时顶替。
4. **人物图合格但本项目没有已批准样片**：只生成一条视频样片，下载和质检后进入用户审核门。
5. **样片已批准但尚无批量指令**：停在 `await_batch_approval`；不得把“样片可以”自行扩大为批量授权。
6. **项目已有明确批量批准**：把本版本登记为同范围最新活动标准，直接按未完成集合串行续跑；不得再问用户复述人物、商品、画质和执行方法。
7. **权限、远端状态或额度阻断**：保留状态并停止，不更换路线、不裁剪锁定音频凑额度。

图片批准按SKU隔离，只对用户实际看到的最终文件路径、版本和SHA-256生效。回读聊天批准证据时必须先还原批准消息发出前实际展示的图片集合；“其他的可以”之类上下文批准只能绑定到当时同屏的其余精确图片，禁止为了包装、清晰度或制作便利换成后来派生的“更可用”合成图。一个SKU获批不代表其他SKU获批；批准前文件、批准后派生文件、重新压缩/合成文件或任何哈希变化都必须重新审核。状态中没有精确批准证据时，不得把 `user_approved` 写成 `true`。

批准与拒绝同时触发存储清理：审核前每个SKU只保留当前待审候选和必要商品源；候选被拒后立即删除该候选及其派生图，不移入异常目录长期占用。五张/整批最终图确认后，每个SKU的`06_人物与商品合成`只保留一个精确批准文件，旧人物图、底图、蒙版、裁切、放大、参考、重压、派生图和旧manifest全部删除；失效HeyGen成片及其QA帧、由失效成片生成的执行包也删除。用户原始白底商品图、原始对标视频、最终音频、文案和必要状态JSON不是生成垃圾，必须保留。删除前验证绝对任务根和批准图哈希；删除后回读目录必须是“每SKU一张批准图”，只在状态/知识库保留失败版本的路径、哈希、原因与删除时间。复用`scripts/cleanup_rejected_media.py`，先只读回读候选，再在活动规则授权下用`--apply`执行。

- 每条有稳定任务 ID、精确 SKU、审核文案或已确认音频、已验收人物图和目标输出路径。
- 人物、声音、姓名、肖像和产品素材的必要权利已确认。
- 产品包装、Logo、文字、颜色、容量和数量已通过人工视觉质检。
- 当前条没有已存在的有效视频、远端 ID 或状态不明的提交。
- 当前条必须存在精确图片批准记录：SKU、最终图片路径、版本、SHA-256、批准时间和用户证据全部一致。
- 实际提交前必须保存 HeyGen 的 `remote_avatar_id`/`remote_asset_id`，并通过远端缩略图或预览确认它与批准图是同一人物、同一商品和同一场景。没有远端ID或无法核对预览时停止，禁止使用当前选中、最近使用或旧任务形象。

## 人物与真实握持标准

- 每个 SKU 建立独立人物身份；该人物不得与同批次其他 SKU 共用同一张脸或同一身份。同一 SKU 的多条口播保持人物一致。
- 人物身份、年龄段、性别表达、服装、房间和使用动作必须从当前 SKU 的真实卖点、目标用户与使用场景推导；不把某一条洗发水样片的“30 岁女性/客厅”硬套给其他 SKU，也不把“每 SKU 不同人物”误解为随机换脸。
- 默认质感为印尼本地日常：自然皮肤和发丝、不过度磨皮，柔和漫射自然光，保留环境纹理与轻微生活杂质，中等饱和度、低对比度、普通手机/CCD 抓拍感。塑料皮肤、影棚级洁净、强滤镜、过锐和一眼 AI 判废。
- 人物底图只负责人物、场景、姿势和空白握持占位；真实商品必须作为锁定源层合成，生成模型不得重画包装、Logo、文字、颜色、容量、数量或比例。
- 合成前先判断白底图是可用真实照片、修图抠图还是渲染/来源不确定；它锁定包装身份，但自身光影、阴影、反射和透视不自动适用于目标场景。校验占位物与真实商品的尺寸、旋转方向、透视轴和中心位置；真实商品必须完全覆盖占位物。不允许通过扭曲包装和标签来迁就错误手势，无法匹配时索取更合适角度的商品图。
- 拇指或前景手指必须在商品前方，支撑手指必须在商品后方。肩/肘/前臂/腕/手指链路、关节角度、受力、重心和接触阴影必须符合现实人体工学。任何占位物残影、双管、悬浮、贴片感、脱手、复制、形变、手指穿插、孤立指尖、断腕感或错误遮挡都直接判废；动作错误时从姿势重做，不在错误底图上继续叠蒙版。
- 本节执行细节统一读取 [商品人物图标准](../../references/product-presenter-image-standard.md)，并在全图和手部商品局部两个尺度自检后才提交用户审核。
- 当前验证通过的输出基准是 720×1280、25fps、柔和的中端 Android 手机实拍质感；不默认使用过度锐利的 1080p。
- 视频完成后至少抽查开头、中段和结尾的手部商品局部；三个位置均通过，才允许进入成片目录。

## 串行流程

1. 锁定当前条并原子更新提交意图；重新计算实际文件SHA-256，必须等于该SKU的批准哈希。
2. 在 HeyGen 中上传/创建或选择与批准哈希绑定的远端形象，保存远端 avatar/asset ID；回读缩略图确认人物、SKU商品和场景一致后才创建人物口播。禁止依赖页面默认选中项、最近使用项或旧形象；不读取 API key，不静默切换后端。
3. 保存远端 ID 后只轮询该 ID；未知状态标记 `unconfirmed`，不得重提。
4. 下载原始视频到外部任务目录并用 FFprobe/FFmpeg 检查文件、视频流、竖屏、完整解码和音轨。
5. 先将首条样片的开头、中段、结尾与批准图逐项对照，再检查口型、人物、产品与包装。人物身份、SKU商品、包装或场景任一不一致，或出现旧形象、灰色占位物、贴片、漂移、损坏，立即标记 `rejected_remote_input_or_render_mismatch`，冻结整个批次，不得继续下一条。
6. 只有用户本次明确要求字幕/本地包装时才做相应后期；不得因此自动升级为 B-roll 完整视频。
7. 更新结果表和 manifest，再进入下一条。

每次提交前把 `method_id=M-CNT-PURE-HEYGEN-001`、`method_version`、`sample_approval`、`batch_approval`、`active_standard_id`、`presenter_id`、`presenter_approval`、`presenter_image_sha256`、`remote_input_binding`、`product_source_sha256`、`audio_sha256` 和当前规则快照写入状态。下载后写入 `render_match_qc`。用户下令批量时，原子更新 `batch_approval` 与标准历史；缺少精确批准或远端绑定字段的旧任务只能迁移到待审核/待绑定状态，不能兼容推断为通过，也不能重复生成。

## 批量门禁

默认先完成一条下载与质检。样片通过不等于批量授权；未明确批准批量时不提交第二条。`ACTIVE_TASK.json`、项目摘要和最新标准索引已有同范围批量批准时视为门禁已过，不重复询问，也不要求用户复述标准。绝不自动发布。
