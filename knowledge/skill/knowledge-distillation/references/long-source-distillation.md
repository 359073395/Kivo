# 长文本蒸馏：基于“一盏神灯”原包的本地适配流程

本流程用于把一本书、课程讲稿、长访谈、会议记录、论文或长文档拆成可调用的方法单元，并优先同步到现有主 Skill；只有职责无法承接时才形成一个或多个候选 Skill。它保留原版的闸门、覆盖率、五路提取、三重验证、数量控制和触发盲测，并按本地知识库规则调整存储与权限。

## 0. 入口闸门

逐个来源检查：

1. 文件存在并已登记来源卡；
2. 已经生成完整文字稿，开头/中间/结尾没有空白、乱码或无意义符号；
3. 内容确实包含可迁移的框架、原则或判断标准；
4. 多文件只能在同一主题、回答同类问题时合并；不同领域分开排队；
5. 方法论较少的叙事、资讯、规范或数据材料不强行生成 Skill，但仍可蒸馏为事实资产、案例库或规则参考。

原版把 5,000 字作为生成技能包的最低体量。本库把它作为“进入多 Skill 长流程”的参考线，不把短而高密度的方法自动拒绝。

## 1. 工作区与续跑状态

- 最终完整文字稿保存在知识库 `资源/raw/`。
- 大量分块、临时候选和运行缓存放在外部蒸馏工作目录。
- 知识库 `项目/` 保存 `状态.md` 或项目摘要：来源 ID、外部工作路径、有效字数、块数、批数、当前步骤、完成批次、目标 Skill 数、阻断与下一步。
- 每完成一步，先把结果落盘，再更新状态；不能先写“已完成”再写产物。

## 2. 全局骨架与批判

通读目录、各章/话题的开头结尾和随机样本，形成：一句话主旨、整体结构、核心问题、3–7 条主张、关键概念、时代/身份局限、未证明假设、失效场景和最强反驳。

随机抽查 3 个块，骨架解释不了任一块时重写一次；最多一次，避免无限重做。

## 3. 分块与五路提取

- 目标 20–40 块；每块约 3,000–15,000 字，优先按章节、小节或话题转折切，禁止在句子中间截断。
- 每批 5 块。按批顺序执行；同一批内只有在用户明确允许且环境支持时才使用并行子任务，否则顺序执行。
- 五路候选：框架、原则、案例、反例/失效场景、作者专有术语。
- 每一路对每一块都写回执：`第 N 块：找到 X 条` 或 `第 N 块：无`。
- 漏回执时只补漏掉的块，最多补一次；仍不完整则接受现状并在最终清单标为覆盖不足。
- 重要候选必须带章节、页码、时间戳或块号以及一小段原文证据；定位不到原文的候选淘汰。

## 4. 候选验证

框架和原则先去重，再过三关：

1. **原文支撑**：书中应在不同章节被论证或应用；转写稿可按不同话题复用或追问展开判断。
2. **事前可用**：能否用于预测、判断或决定尚未发生的事情；只能事后解释的淘汰。
3. **不是泛常识**：公开模型本身不再做成 Skill；作者补充的阈值、判断标准和操作步骤可以保留。

案例、反例和术语是构建材料，只去重，不用“是否常识”批量误杀。术语回写到骨架，反例负责形成“不适用范围”。

原版纠偏参考值：书的正常通过率 30%–50%，高于 65% 或低于 8% 时重筛一次；转写稿正常 15%–30%，高于 45% 或低于 5% 时重筛一次。最多重筛一次。通过数仍为 0 时停止生成 Skill，保留候选和淘汰原因。

候选之间或与活动规则发生会改变结论的未决冲突时，先汇总冲突双方、来源、影响和处理选项询问用户；等待期间继续非冲突分块，冲突块标记 `conflict_pending_user`，不得进入最终方法或 Skill。

## 5. 归并为方法并匹配现有 Skill

按“用户会在同一个问题场景中需要它们”归组，而不是按相似关键词归组。每组包含一个主框架、相关原则、案例和反例。先匹配现有七个主 Skill 的职责与模式；能承接的更新现有 reference/RUNBOOK，既没有框架也没有案例的组不进入执行层。

数量参考：

| 有效字数 | 目标数量 | 硬上限 |
|---|---:|---:|
| 5,000–20,000 | 1–3 | 3 |
| 20,000–60,000 | 3–5 | 5 |
| 60,000–150,000 | 4–7 | 7 |
| 超过 150,000 | 6–10 | 10 |

转写稿因信息密度较低，目标和上限各减 2，最低为 1。超出上限时优先保留能让普通人完成具体任务的单元。

确需新增 Skill 时，`description` 必须写真实触发语句、排除条件和前置 Skill；正文必须包含核心判断、步骤、可观察的做对/做错信号、不适用范围和出处。复杂方法可以使用 `references/`、`scripts/`、`assets/`，不受原包“只有一个 SKILL.md”的限制。

## 6. 双层触发盲测

只向测试者提供候选 Skill 的 `name` 和 `description`：

- 同源混淆：应该触发同批另一个 Skill 的题；
- 宿主混淆：应由通用能力或 `knowledge-distillation` 处理、候选 Skill 都不该触发的题；
- 必考题：`帮我把这本书蒸馏成技能` 必须仍触发 `knowledge-distillation`，不能被产出的阅读/学习 Skill 抢走。

答错后修改对应 description，并重测全部题；最多两轮。仍失败的标记低置信，不自动注册为活动 Skill。

## 7. 交付与安装

交付方法清单、现有 Skill 路由/同步结果、仍为候选的内容、未决冲突、淘汰记录和覆盖不足；只有确需新增 Skill 时才交付候选 Skill 与触发测试题。默认不自动安装第三方或新生成 Skill；只有用户明确要求安装，且结构验证、边界检查和冲突检查通过后才注册。旧活动 Skill 必须可恢复。
