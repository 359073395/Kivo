# 来源文字化

本流程只负责把来源转换成完整、可追溯、可检索的文字稿。转换完成不等于已经蒸馏。

## 通用规则

- 原始大文件保留在外部本地工作目录；未经用户明确要求，不删除原件。
- 最终文字稿保存在知识库 `资源/raw/`，使用 UTF-8 Markdown；临时音频、抽帧、OCR 图片、模型缓存和中间文件不进入知识库。
- 每个来源只保留一份权威文字稿；避免同时保存内容相同的 `.txt`、`.md` 和多份副本。
- 文件头记录：来源 ID、标题、类型、原件外部路径或 URL、哈希（本地文件可用时）、作者/发布者、访问或获取日期、语言、时长/页数/幻灯片数/工作表数、转换工具、完整性状态、缺失范围和生成时间。
- 无法读取的字词使用 `[听不清 00:00:00]`、`[OCR不确定 p.12]` 或等价标记，禁止猜补。

## 视频与音频

1. 记录原文件名、时长、编码、语言和哈希。
2. 在本机临时目录抽取 16 kHz 单声道音频；优先使用隔离环境和本地 Whisper/faster-whisper，不能默认上传私有媒体到云端。
3. 覆盖完整时长转写，保留自然段级起止时间戳，连续碎片可合并但不得删改原意。
4. 视频还要检查重要字幕、屏幕文字、图表、软件操作和只存在于画面的信息；必要时做关键画面 OCR，并以 `[画面 HH:MM:SS]` 写入文字稿。
5. 稿件依次包含：元数据、带时间戳逐字稿、重要画面信息、无法识别段落；为兼容来源工作流，可在末尾附无时间戳纯文本，但不再另建重复文件。
6. 将最终稿保存到 `资源/raw/sources/视频/` 或 `资源/raw/sources/音频/`；`资源/raw/transcripts/` 只作为兼容旧稿入口。

抽帧只能帮助补充画面信息，不能替代全程音频转写。只处理开头、结尾或若干片段时，状态必须是 `partial`。

## PDF

1. 记录总页数、文件哈希和是否为可搜索文本。
2. 文字型 PDF 逐页提取；扫描型或混合型 PDF 对所有无文本页做 OCR。
3. Markdown 中保留 `## 第 N 页` 或等价页锚点、标题层级、段落、列表、表格、脚注和图表说明。
4. 表格不能只写“见原表”；保留表头、单位、行列关系和无法还原的单元格说明。
5. 公式保留可读表示；图表至少记录标题、坐标、图例、主要关系和无法确定的部分。
6. 完成后对照总页数，缺页或乱码页列入未解决项；最终稿保存到 `资源/raw/sources/文档/`。

原 PDF 默认留在外部工作目录。知识库保存文字稿、来源卡和外部原件路径/哈希，从而节省主库空间并保留追溯能力。

## DOCX、PPTX 与网页

- DOCX：保留标题层级、正文、表格、脚注/尾注、批注含义和图片说明。
- PPTX：按幻灯片顺序保留标题、正文、讲者备注、图表和关键视觉关系。
- 网页：保存标题、作者、URL、访问日期、正文、必要子页范围和更新日期；动态或折叠内容要明确是否已展开读取。
- 受版权限制的第三方网页以详细释义和少量必要引文为主，不复制整套站点或付费内容。

## 图片、表格与其他格式

- 图片：全文 OCR，加上版式、图表、按钮或流程关系说明；标注不确定字符。
- XLSX/CSV：记录工作表、表头、单位、公式口径、数据范围、空值和关键表格；可执行模板本身有必要时保留轻量原件，否则保留规范化表格文字。
- 不支持的格式：登记 `blocked` 或 `unreadable`，列出需要的工具或替代文件，不得根据文件名推断内容。
