# 蒸馏验收门禁

## 文字化门禁

- [ ] 视频/音频时长与逐字稿覆盖范围一致，缺失时段已列出。
- [ ] PDF 总页数与文字稿页锚点一致，OCR/乱码/缺页已列出。
- [ ] 网页正文、必要子页和访问日期已记录。
- [ ] 最终 Markdown 文字稿在知识库内，原始大文件与临时缓存在库外。
- [ ] 来源卡含路径或 URL、日期、哈希（可用时）、工具和完整性状态。

## 内容门禁

- [ ] 事实、作者观点、用户规则、AI 推断、冲突和未知已分开。
- [ ] 关键结论可回到页码、时间戳、章节或子页核对。
- [ ] 已检查重复、时效、适用条件、反例与遗漏。
- [ ] 没有把抽样、封面、标题或局部转录当成完整学习。
- [ ] 关键字段分别记录 `provenance`、`verification`、`governanceStatus`，没有把“原文核验”误当“活动执行权”。
- [ ] 扫描资料的每个锚点同时记录 OCR 页标与印刷页码；不存在时用 `null`，不猜填、不把多锚点批量写成同一核验状态。

## Skill 门禁

- [ ] 重复出现且流程相对稳定；一次性任务未被硬做成 Skill。
- [ ] `name` 与 `description` 能准确分诊，并与相近 Skill 划清边界。
- [ ] 有输入、步骤、判断、检查、停止、异常和反馈。
- [ ] 外部依赖、授权边界、费用或高影响动作已说明。
- [ ] 有真实例子、回测或明确验证方案。
- [ ] 结构验证通过，旧版本可恢复，活动入口没有未解释的重复。

## 知识库门禁

- [ ] 来源卡、文字稿、权威资产、缺口队列和日志均已更新。
- [ ] 新规则状态正确：候选、已验证、活动、已废弃或归档。
- [ ] 每条新活动规则能反向回溯到用户原话或真实结果，并通过活动规则编译门；不能通过时降级为协议说明、测试、来源修正、候选或参考。
- [ ] Manifest 已更新并通过缺失、哈希和未跟踪文件检查。

任一硬门禁失败时，状态只能是 `partial`、`blocked` 或 `candidate`，并明确下一步。
