# Knowledge Distillation

把来源中的知识或用户在真实任务中表达的隐性经验，编译成以后可以重复执行、判断、检查、停止和迭代的工作资产。蒸馏不是普通摘要，也不是直接复制原文。

## 先定位知识库

1. 依次从当前任务/输入路径上级、当前已加载 Skill 的真实目标路径上级和 `KNOWLEDGE_BASE_ROOT` 查找 `knowledge-base.json`；仅当标记文件存在时才回退到 `D:\Knowledge`。工作目录在知识库外不代表知识库不存在。
2. 读取根目录 `AGENTS.md`、`资产/规则/规则权威与变更协议.md`、`资产/方法论/知识蒸馏总规则.md` 和 `辅助/维护/蒸馏检查清单.md`。
3. 读取 `资产/规则/蒸馏知识自动调用与Skill同步协议.md`，确认本次蒸馏怎样回写现有 Skill，而不是只生成孤立知识页。
4. 来源、最终文字稿、蒸馏结果、日志与队列均使用相对知识库根目录的链接。

## 选择模式

- **资料蒸馏**：书籍、访谈、课程、文章、网页、PDF、视频或音频。先完成文字化，再读 [references/source-distillation.md](references/source-distillation.md)。来源超过约 5,000 字、包含多个章节或预期生成多个 Skill 时，再读 [references/long-source-distillation.md](references/long-source-distillation.md)。
- **个人技能蒸馏**：把用户与 AI 完成真实工作的过程固化为 Skill。读 [references/personal-skill-distillation.md](references/personal-skill-distillation.md)。
- **现有 Skill 再蒸馏**：根据真实运行、用户纠正和结果复盘，删重复、补边界、更新判断与停止条件。沿用个人技能模式，但保留旧版本与变更原因。

任何视频、音频、PDF、扫描件、演示文稿或网页来源，先读 [references/source-textualization.md](references/source-textualization.md)。视频/音频还要读 [references/local-video-transcription.md](references/local-video-transcription.md)：以下载留档的原版 `video-transcript` 为基线，只应用其中列明的六项本地化修正，先检查本机依赖，不得假装模型已经存在。完成前读 [references/quality-gates.md](references/quality-gates.md)。

## 不可变规则

- **先文字化，后蒸馏。** 最终清洗后的完整文字稿保存在知识库；原始大文件与临时转换缓存留在知识库外。
- 视频/音频必须覆盖完整时长；PDF/文档必须覆盖全部页或明确列出缺失页。抽样、抽帧、标题和局部摘录只能标记 `partial`。
- 视频文字稿保留时间戳；重要屏幕文字、演示步骤和纯画面信息用 OCR 或文字描述补入。
- PDF 先做全文提取；扫描 PDF 做全页 OCR；保留页码、标题层级、表格、列表、脚注和无法识别标记。
- 不把未读内容写成作者观点，不把作者观点写成事实，不把 AI 推断写成用户规则。
- 关键字段与每个来源锚点分别记录 `provenance`（出身）、`verification`（核验程度）和 `governanceStatus`（执行权）；扫描资料同时记录 OCR 页标和印刷页码。原页核验不自动赋予执行权，现代编译也不得冒充作者原话。
- 冲突会影响结论、范围或 Skill 执行且无法由当前用户指令/活动权威直接裁决时，先列出冲突双方、来源、影响与选项并询问用户；答复前只完成非冲突部分，冲突部分标记 `conflict_pending_user`，不得写成最终总结或同步执行层。
- 资料蒸馏先确定目标：提炼 `what they do`、`how they think`，或解决一个具体问题。
- 一份大来源可以产生多个边界清楚的方法单元，并优先同步到现有主 Skill；只有现有职责无法承接时才产生候选新 Skill，不能为了“有 Skill”而把纯参考知识硬改成流程。
- 新 Skill 必须包含准确的触发描述、输入、执行、判断、检查、停止、异常与反馈；复杂细节放入 `references/`、`scripts/` 或 `assets/`。
- 一次来源或一次成功默认只生成候选规则。用户明确确认、复用、回测或真实结果验证后，才能升级为活动规则。
- 用户明确要求某批蒸馏知识以后自动使用时，批准的是经过查重、冲突处理、范围化和停止条件审查的方法，不是来源中的全部观点。符合门禁的方法必须同步到已有主 Skill 的活动方法路由。
- 对“测试→批量”的重复工作，单个样片满意只通过样片门；只有用户明确下令批量执行的版本才成为同范围最新活动标准。批准时更新 `资产/规则/最新批量批准标准索引.md`、项目状态和行为回归；之后的新测试若未获批批量，只能保持候选。
- 尊重授权、隐私与版权边界；不把整套第三方知识库或无权传播的付费内容重新打包发布。

## 固定交付物

每批蒸馏至少产生或更新：

1. `资源/来源索引/` 中的来源卡；
2. `资源/raw/` 中的最终完整 Markdown 文字稿，或清楚说明为什么没有文字稿；
3. `资产/` 中的可复用知识、方法卡或决策单元；
4. 固定交付“Skill 路由/同步结论”：说明每个可执行方法进入哪个现有主 Skill、为何自动/候选/待核实；用户确认或验证通过且无冲突的方法必须在同一轮更新对应 Skill 或 RUNBOOK，不能只写“以后可用”；
5. `辅助/摄入队列/` 中的未读、冲突、缺证据与下一问题；
6. `辅助/日志/知识库日志.md` 中的变更记录；
7. 对用户明确批准或真实批次验证的工作方法，必须有可运行的行为回归，至少验证知识库定位、项目状态恢复、正确路线、审核门和停止条件。只有标题/段落/链接检查不算完成。

创建或大改 Skill 时，按当前环境的 `skill-creator` 规范检查结构并运行验证器。不要仅因用户说“总结”就擅自安装或覆盖一个同名活动 Skill；先查重、比较边界并保留可恢复版本。

同类能力优先合并进现有七个主 Skill。只有七个入口都无法合理承接，且新流程会重复出现、有独立触发、输入、输出、检查和停止条件时，才提出新 Skill。

## 停止条件

遇到下列情况停止对应来源或规则升级，并明确报告：来源无权访问、原件损坏、转换覆盖率不足、关键页/时段缺失、会影响结论的冲突尚未获得用户裁决、输出会覆盖用户原文、同名 Skill 边界冲突、需要上传私有材料、或需要用户决定适用范围。无冲突部分可继续处理。

真实任务结束后，询问一次简短反馈；把反馈写成候选更新并记录实际效果。未经用户确认，不自动扩大规则范围或执行发布、发送、付款、删除、上传等外部动作。
