# 蒸馏工作流

开始前读取知识库根目录 `资产/方法论/知识蒸馏总规则.md`、`辅助/维护/蒸馏检查清单.md` 和专门入口 `skill/knowledge-distillation/SKILL.md`。本文件只负责摄入与回写衔接；具体文字化和蒸馏由 `knowledge-distillation` 执行。

## 1. 盘点与登记

盘点用户提供的每个文件或URL，记录类型、路径/URL、日期、作者、可读性和处理状态。最终清洗后的 Markdown 文字稿放入 `资源/raw/`；大型原视频、原音频、原 PDF/文档和生产素材保留在外部本地工作目录，并在 `资源/来源索引/` 建来源卡。

视频/音频必须完整转成带时间戳文字稿；PDF/文档必须全文提取或全页 OCR。抽样画面、局部转录和缺页稿只能标记 `partial`。网页保留URL、访问日期、标题和可复查上下文；图片资料使用OCR并标记不确定文本。

## 2. 写入前分流

搜索文件名、标题、别名、标签和正文，检查重复与时效。判断它属于项目、资产、资源、灵感、归档，还是可晋升为Skill的方法。

## 3. 转交专门蒸馏 Skill

调用或按 `knowledge-distillation` 执行“先文字化、后蒸馏”。本 Skill 不再维护另一套独立蒸馏流程。

## 4. 提取知识

至少区分：

- 带来源和日期的事实；
- 作者观点；
- AI推断；
- 可执行方法与步骤；
- 适用条件、限制、反例；
- 与现有知识的冲突；
- 未知、证据缺口和下一问题。

## 5. 编译到权威位置

更新最窄的权威页面。个人IP知识进入 `资产/个人IP/`，商品转化和短视频经营知识进入 `资产/带货视频/`，项目状态进入 `项目/`。不要按课程名堆叠专业知识，也不要为同一概念制造近义重复页。

每个可执行方法还必须指定现有主 Skill 和模式。用户确认或验证通过的方法回写对应 Skill 的 reference/RUNBOOK；未验证内容保留候选。冲突若影响结论且现有权威无法裁决，先询问用户，答复前不关闭该冲突部分。

## 6. 输出与反馈

根据任务生成决策简报、报告、计划、脚本、选题、清单、图片/视频Brief或行动项。保存可复用部分，把证据缺口、矛盾、拒绝的假设和下一步写回队列或项目摘要。

## 7. 记录

在知识库日志中记录日期、来源、变更页面、Skill 同步结果、关键判断、未解决冲突和下一步。不可读或不支持的来源必须报告，不能静默跳过。

会话交接、目录结构、Skill 文件和恢复脚本都不能单独证明“知识已经蒸馏”。完成前必须检查 `资源/来源索引/` 和对应 `资产/` 是否出现真实、可复用、可追溯的内容。
