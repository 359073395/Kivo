# 标题与详情：关键词对比、核心需求保留与交付检查

状态：active_process_only，COM-015执行补充。直接依据：[2026-10-13用户纠正与长期执行授权](../../../资源/来源索引/2026-10-13_标题详情关键词与交付自检纠正.md)。与COM-004价格排除、身份与事实门禁共同生效；不新增外部权限。

## 触发与恢复

用户要求优化商品标题/详情/某SKU，比较自家与对标或“官方优化”时自动读取本页，不等用户提醒知识库。先定位活动库，再恢复SKU、当前用户纠正、原稿与可用对标；只有SKU时先查自家资料，标明来源日期。历史导出不冒充实时状态，找不到的必要事实只问最小缺口。

输入按来源分为：自家事实、用户当前确认、对标原文、官方/平台生成文案、测量数据、未知/冲突。用户提供的对标文案可以直接分析，明确“用户提供、链接未核验”；自主检索的对标按现行规则附可查验链接。外部标题和评价不证明本品功能或热搜量。

## 每次执行

1. **先明确购买理由**：用当前资料写清产品给谁、解决什么具体需求、靠什么真实特点；至少保留一个有自家依据的核心需求在标题和详情开头。不能用容量、人群或泛泛“清洁/护理”替代全部真实卖点。纯清洁产品本身就是清洁需求时不强行创造更强功效。
2. **逐词比较**：从自家原标题、详情、对标和官方稿抽取有用的品类、需求、功能、成分、规格、人群、场景及长尾表达。内部记录每个重要候选词的来源、自家重叠依据、保留/替换/排除决定及原因。没有更好的新增词就说明多数重叠，不为显示工作量编词。
3. **保留有用覆盖**：核心品类及购买需求前置，真实差异、人群、场景自然衔接。保留有价值的中英文词及自然同义表达，不为短而删，也不重复堆词凑长。255字符为公司手册的撰写参考，不称已核实的当前平台上限；报告字数需实际计算。资料不足不靠泛词或无依据承诺填满。
4. **只处理具体问题承诺**：对未经支持的速度、保证、技术、医疗/生发、安全、认证、适龄等逐项排除或列为待核，保留其余有依据的需求与特点。比如含人参不证明快速生发，但不能因此把有资料支持的掉发/受损头发护理需求一并写没。“帮助/护理”不是把虚假功效合法化的修饰语，仍需自家依据。
5. **准确接纳纠正**：用户确认“有人参”立即更新本SKU事实；不反复追问同一点，也不外推整套配方或效果。用户说“我觉得可以加”“差不多”按候选，不称产品实测验证。品牌/容量等去留按当前SKU指令执行，不把其他SKU例外推广。
6. **比较必须有实质增量**：与原稿、对标或官方稿比较核心需求、有效关键词、信息清晰度、事实一致性与可用性；指出具体保留、补充或修正。无增量时继续改，或坦率说明没有足够信息改得更好，不强行换词。没有同口径数据不得声称流量/成交/转化提高，更不先验断言官方或AI一定更好。
7. **一份推荐成稿**：默认交付一版明确推荐的标题与详情。中文说明用途与含义；印尼语标题、详情各自放独立复制框。除非用户要求，不同时堆多个备选让用户选择。用户只问比较时按问题范围回答，不强制重复整份详情。
8. **内部说明留在复制框外**：未知项、证据缺口、优化理由、待验证句都不得混入可用商品文案。不要把“没有其他材料信息”等内部缺口当详情卖点。推荐标题/详情不含未确认断言，即使有脚注也不行。

## 交付前自检与停止条件

- 核对精确SKU、来源版本、当前纠正与本款例外；自家/对标没有混用。
- 对照候选词逐项核查处理结果；关键购买理由仍在标题和详情首段，不被泛词淹没。
- 年龄/人群要求有结论：有证据则准确写；未知则在中文说明列出；不适用年龄维度（如发动机清洁剂）则不硬套儿童。不得无声漏掉用户要求。
- 已知品牌、型号、规格、数量不漂移；冲突仅停止相关字段，不停止已有事实支持的部分。
- 无已验证搜索数据时，只说语义相关/需求覆盖，不称高流量或已提升转化。对照稿不能代替本品功效依据。
- 中文标签、中文含义和独立印尼语复制框齐全；只给一份推荐，实际内容可按用户要求复制。
- 任何项失败先自行修改再交付；仍需用户事实时只列关键缺口，不再次让用户重讲规则。线上操作依然另需当前授权。

## 检查工具与回归

2026-10-19增量工具：[共享产品资料与交付检查](commerce-quality-tools.md)。完整文案已有数字/规格或需跨图片/视频一致性检查时，在下方原检查基础上运行`commerce_quality.py check`；传`--listing-review`可合并原检查并核对SKU/稿件一致。先扫描后按真实字段绑定，空禁词清单经审查可用。不能用新增工具代替核心需求、逐词取舍和双语交付；图片成品与非数字功效仍须语义/视觉复核。

`scripts/validate_listing_delivery.py <库外检查JSON>`检查SKU事实引用、重要关键词处理覆盖、核心需求在成稿中保留、未确认声明隔离、人群状态、单版双语交付及效果判断来源。每次完整标题/详情交付前使用；比较类任务可用同一人工检查而不强造标题。检查JSON及结果放机器配置的productionWorkRoot下，不进知识库。

检查器依赖输入的真实来源与人工语义判断，不自动证明印尼语地道、产品功效或营销效果，也不授予外部权限。无法确定的词不自动降级为基础清洁文案，按局部缺口处理。

执行 `python -B -m unittest discover -s skill/tiktok-commerce-operations/tests -p test_listing_delivery.py`。正反用例包括：有依据的核心词保留、泛化掉卖点、无原因删词、候选功效进成稿、年龄无依据、品牌/克重跨SKU套规则、假高流量、材料不足与正确分框。修改检查器或规则后运行；正常每款仅运行本次交付检查，不重复整库回归。

## 反馈

用户纠正立即回到本款事实/候选词及成稿，不以解释代替修订。只有真实、同口径结果或用户明确批准才登记成功基准；生成样稿、检查通过或官方工具输出不等于有效性验证。复盘仅保存可观察的删改、阻止错误与实际结果。
