# TikTok 商品运营最新规则

本文件是 SKU 商品运营系统的当前覆盖层。旧模块与本文件冲突时，以本文件为准。

本文件也受 `资产/规则/规则权威与变更协议.md` 和 `资产/规则/活动规则总表.md` 约束。未登记的旧数字、账号和默认值不因出现在脚本/对话中而生效。

## 边界

- 知识库保存规则、Skill、知识、项目摘要、manifest 和最终复盘。
- 店铺导出、价格源、活动模板、报告和浏览器下载属于单独本地工作目录。
- 机器路径读取 `辅助/配置/machine-paths.local.json`，不得把旧电脑盘符当成事实。

## 店小秘周更

1. 只处理当前映射中已经存在的店铺，不新增、删除、移动或重命名店铺目录。
2. 严格逐店验证身份、强制 300 条每页、同步完成、全选数一致、导出数和 XLSX 可读性。
3. 某店失败时不覆盖该店旧产品表；其余店可在身份与隔离条件可靠时继续。
4. 在线产品数、同步成功数和导出 SKU 明细数是三个口径，必须分开汇报。
5. 取消旧的固定任务 ID 交接；当前任务继续完成后续或保存本地会话交接。

## Flash Deal

1. 每店必须使用该店当前活动页面下载的原始 `Flash Deal.xlsx`。
2. 默认直接原位填写这份 `Flash Deal.xlsx`，不创建 `Flash Deal_已填写.xlsx`。
3. 默认不创建备份和单独审计表；用户明确要求时才创建。
4. 只填写经过验证的 `Product_id` 与 `Deal Price`，并保持官方 OOXML 包结构。
5. SKU 是仓库和定价键，上传必须使用该店自己的 product ID，禁止跨店复用。
6. 同一店铺内按 Product ID 分组后，若对应多个不同SKU，则整个 Product ID 跳过，不论最终价是否相同；2026-09-22用户明确确认，无需逐次询问。单SKU商品遇到清仓/下架、缺价或价格冲突时停止，不猜测。单个Npcs SKU不因件数前缀自动排除，仍按统一价格规则精确匹配或拆算。
7. 写入前先在内存完成全批次校验；写入后重新打开原路径核对目标单元格、ZIP 条目和工作簿有效性。
8. Flash Deal 必须重建为“当前全部合格 product ID”，不能只追加本周新增 ID；已在线的旧 ID 与本周新增 ID 要同时保留，离线 ID 才移除。
9. 默认不参加大促；只有用户对本次活动单独明确告知参加时，才切换到另行确认的大促口径。
10. 先生成并校验统一SKU价格表：价格1=当前已登记仓库价格源的猫店参考价先加8000，再乘1.05（整数IDR向上取整）；当前源由 `current-warehouse-source.json` 指向（2026-10-12更新为 `10.12印尼所有产品及定价.xlsx` E列，9.12和7.21版仅供历史对照）；价格2=`Y仓 TK SHOP SKU 售价_活动价.xlsx`平台活动价；最终价取两者较低值。旧版本B、旧Flash价格和旧安全线回退不再参与未来定价。
11. 2026-10-10用户明确确认：Npcs组合最终价=基础SKU最终单件价×N；先确定同口径的最终单件价，再乘数量，单件价缺失时停止，不用独立组合报价替代。只有用户逐项确认并登记的一对一SKU别名或精确SKU定价例外可以绕过一般门禁；未登记SKU不得模糊匹配。已确认别名：`HK FOOT PASTE` → `HK FOOT PASTE 足贴`；已确认定价例外：`626-Expce Herbal Tea` 价格1为空时使用价格2 `59,520 IDR`，不得推广到其他SKU。
12. 同一SKU可对应同店多个Product ID及跨店不同Product ID；Product ID必须店铺独立，跨店重复是异常。同一Product ID多个不同SKU时整项跳过，并在结果中报告；必要源价缺失、非数值、冲突的单SKU商品仍停止并询问用户，不得猜价或静默少填。
13. 后续Flash Deal只读取已校验统一SKU价格表的最终价格。官方模板预留行不足时，新增行必须从写入前保存的纯净空白样式复制，禁止复制已经填入商品的行。写后除常规值回读外，必须直接扫描 OOXML：每个数据行恰好一个 A/B 单元格、无重复单元格引用、Product ID 唯一、C/D 等未授权列无值、数据行数与合格集合一致。结构检查失败时不得交付或上传，并保留写前文件。

## Listing

- 合规和事实是发布门禁，不参与可被其他分数抵消的加权。
- 只给当前证据支持的印尼语成稿；未知规格不放入“可直接发布”文案。
- 图片任务必须对应诊断问题，并锁定真实产品不变量。
- 默认只诊断和生成本地产物，不自动上传或改线上 Listing。

## 选品

- 先做市场机会，再做自有 SKU 承接；没有自有 SKU 也可以运行 `market` 模式。
- 正式测试决策需要当前证据、有效链接、数据质量、硬风险、规则/AI 门禁，以及自有 SKU 的利润、库存和上架准备度。
- 市场数据必须标明采集时间，并满足本次决策所需时效。没有当前用户/平台确认的固定时限时，不得由 AI 自拟“48 小时”等永久阈值；历史数据只能作上下文。
