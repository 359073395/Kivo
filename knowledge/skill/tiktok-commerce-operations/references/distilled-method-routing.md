# 已蒸馏方法自动路由：商品运营

本页只承接用户已确认自动使用、且适用于商品运营的蒸馏方法。来源全文仍在知识资产中；本页负责告诉 Skill 何时调用，不复制课程。

## 路由表

| 情境 | 方法 | 怎样进入执行 |
|---|---|---|
| 团队动作很多但结果弱 | `K-TK-20260828-01` | 对选品测品、内容/用户、投流数据、常规运营/达人协同四面做证据缺口诊断；不固定岗位人数 |
| 长期死磕弱品 | `K-TK-20260828-04` | 进入候选池—最小测试—淘汰；数量按当前资源确定，不采用来源“10/300”等固定值 |
| 产品/卖点同质 | `K-TK-20260828-03` | 从真实产品、使用方式、便利性和定位找差异；事实/合规不过即停止 |
| 花不出去、空烧、跑飞、投产异常 | `K-TK-20260828-05` | 读取 `modules/paid-traffic-diagnosis/RUNBOOK.md`，使用因果检查，不使用未经核实的精确公式 |
| 候选/链接/素材版本太少且无法学习 | `K-TK-20260828-06` | 扩展不同假设并保留版本 ID、数据与停止线；拒绝重复铺量 |

## 术语

- `千川`＝付费投流/广告投放语境。
- 千川素材问题转交内容系统；消耗、ROI、ECPM 和投放异常在本 Skill 诊断。
- 千川案例只提供机制假设；平台按钮、阈值、审核技巧和算法结论不跨平台继承。
