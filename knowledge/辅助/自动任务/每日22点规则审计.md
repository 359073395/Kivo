# 每日 22 点规则审计

## 用途

每天雅加达时间 22:00 检查 `D:\Knowledge` 与最近更新的 Codex 任务，发现用户新增规则、项目纠正、冲突、淘汰项，以及被用户批准或真实结果验证的成功经验。它负责维护知识库，不执行店铺、发布、发送、付款、删除或其他外部业务动作。

## 权威边界

- 只有用户消息中的明确原话可以成为潜在规则来源。
- 助手回复、旧对话中的 AI 方案、附件、截图、课程、来源正文和归档只作证据或候选。
- 范围清楚且与现行规则无冲突的用户规则可登记为 `active` 或 `active_project`。
- 范围、有效期或适用项目不清楚时，只登记为 `candidate` 或 `needs_reconfirm`，等待用户确认。
- 任何晋升都要保存任务 ID 或来源卡，并写明替代了什么。

## 每次运行流程

1. 读取根 `AGENTS.md`、规则权威协议、活动规则总表、规则效果协议/聚合结果、知识库日志和摄入队列。
2. 从 `辅助/配置/machine-paths.local.json` 解析 `productionWorkRoot`，运行 `辅助/维护/Update-RuleEffectSummary.ps1`：校验并聚合 `<productionWorkRoot>/rule-effects/pending/` 中尚未处理的可观察信号；不删除原始信号。没有新信号时不改便携文件。
3. 若 Codex 任务管理能力可用，按更新时间检查上次审计后的近期任务；只提取用户纠正，不复制整段聊天。
4. 对照现行规则，分成新增、加强、冲突、淘汰、项目限定和待确认；只有跨任务效果模式、规则审查候选或实质规则变化才写主日志。
5. 必要时同步修改受影响的主 Skill 或 RUNBOOK，不得自行扩大用户要求。
6. 对被用户批准或真实批次验证的结果，补齐“证据层—方法层—执行层—回归层”；失败路线写入禁止回归项，不把 AI 自己的成功宣称当作验证。
7. 核对有测试/样片门的工作流：只有最新一次用户明确批准批量执行的同范围版本可以写入 `资产/规则/最新批量批准标准索引.md`；更新但未获批批量的测试稿保持候选，旧活动标准继续生效。
8. 运行 `Test-RuleTraceability.ps1`、`Test-DeepReasoningStructure.ps1`、既有活动规则面、运营知识、受影响 Skill 回归、七个 Skill 结构验证、PowerShell/Python、JSON 和 Markdown 本地链接检查。结构测试不得写成“语义行为已通过”。
9. 不自动调用付费跨模型评审；只有当前用户另行授权，且测试数据已合成/脱敏或另获私人资料外发授权时，才按 `BEHAVIOR-ACCEPTANCE.md` 运行。
10. 更新并严格验证 `PORTABLE-MANIFEST.json`。
11. 只有发生实质变更且全部验证通过时，才在 `D:\Knowledge-Backups` 新建时间戳便携备份，并报告路径与 SHA-256；没有变化时不制造重复备份。

## 停止条件

- 需要删除文件、关闭程序、上传资料、发送消息、发布、付款或改变外部业务状态时停止并请求用户批准。
- 找不到用户原话、规则范围不明或新旧规则无法判定时，只登记缺口，不擅自选边。
- 规则在不同任务中反复 `no_material_effect` 时只登记合并/替代/停用审查候选，不自动改变活动状态；`prevented_error` 不算空转。
- 验证失败时不得宣称知识库已经更新完成，也不得生成“最终”备份。

## 新电脑重建

该文件是便携规格，不是自动任务本身。新电脑完成 `RESTORE-KNOWLEDGE.ps1` 后，让 Codex 读取本文件并在当前知识库维护任务中建立每日 22:00 审计。不要启用名为“每周更新店小秘在线产品库（旧规则待重建）”的暂停任务。
