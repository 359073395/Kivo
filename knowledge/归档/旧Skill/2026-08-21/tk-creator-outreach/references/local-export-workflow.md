# 本地免费导表工作流

## 支持格式

- `.csv`、`.tsv`：自动检测逗号、制表符或分号分隔。
- `.xlsx`：使用 Python 标准库读取，不要求安装 Excel、pandas 或 openpyxl。
- `.xls`：先从原平台另存为 `.xlsx` 或 `.csv`；旧二进制格式不直接处理。

本流程不调用 TikTok API、ScoreHub 或其他付费达人数据库。Codex 自身的现有订阅或使用额度不属于第三方数据费。

## 表头识别

脚本在每个工作表前 30 行中寻找最可能的表头，优先选择包含达人账号/主页及国家、语言、粉丝、类目等字段的工作表。常见中英文列名会自动映射，并将结果写入 `header_mapping.json`。

若识别错误，依次使用：

1. `--sheet "工作表名"`
2. `--header-row 3`
3. `--mapping assets/header-mapping.example.json`

映射 JSON 支持“源表头 → 规范字段”，也支持“规范字段 → 一个或多个源表头”。不要把含义不同的列强行映射到同一字段。

## 两次运行

### 第一次：原始后台导表

目标是清洗、硬筛、计算已有证据并生成复核队列。大多数达人会因缺少内容/评论证据显示“待补数”，这是正确结果，不是失败。

默认漏斗：

- 全量：规范化、去重、硬筛和数据体检；
- 前 100：标准复核；
- 前 40：深度复核，可按团队承接能力设为 30–50。

队列先后综合使用已有完整评分、证据覆盖率和合法导出的近期播放/互动等信号，但不会把该顺序伪装成原版最终分。

### 第二次：已填写的深度复核表

在 `deep_review_queue.csv` 中补充：

- `reviewed_video_count`：建议 10–20；
- `reviewed_video_urls`：用 `|` 分隔；
- Hook、产品演示、表达、制作、稳定性证据与对应分数；
- 代表性评论购买意向、商品内容比例、痛点/演示/CTA 证据与对应分数；
- 风险核查证据与扣分；
- 一条真实近期内容观察，并在核验后设置 `personalization_verified=true`。

把填好的文件重新传给 `run`。它本身保留全部规范输入字段，因此无需手工合并回原始导出。

## 成本与边界

- 原始导出、脚本运行、CSV/XLSX 映射均不产生第三方数据费或 API 费。
- 最近 10–20 条视频和评论证据仍需人工查看，除非用户另行提供合法、已授权的数据源。
- 所有邀约只生成草稿；外发、寄样和商务承诺仍由人工批准。
