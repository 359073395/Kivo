# 七个主 Skill 自动运营总图

用户只描述目标。AI 先理解本次具体问题、对象、阶段、证据和真实瓶颈，再自动选入口、定向读取规则与蒸馏知识、执行最小授权动作、检查结果并回写经验。`allow_implicit_invocation` 对七个主 Skill 均保持开启；用户不需要提醒“结合我的问题”或“调用知识库”。

任何入口的交付都必须先回答本次问题，再说明针对当前对象的判断、优先动作、成功信号和停止条件；不输出与问题无关的完整知识清单。先按 `SYS-012` 判定问题属于纯事实、纯执行、判断/选择、价值/情感/伦理或混合任务，再选用相应深度；Skill 路由和问题类型路由是两层不同入口。

## 跨入口的主导思考层

只要任务包含判断或选择，不论最终由哪个业务 Skill 执行，都必须在内部对同一批事实同步运行两套固定检查：

```text
同一批事实与最新反馈
  ↔《毛选》过滤器：矛盾阶段｜主要矛盾｜节奏
  ↔ 第一性原理过滤器：还原等式｜杠杆变量｜边界常量｜至少2个风险标注假设
  → 业务硬门禁内的动作与反馈
```

两套检查无先后，内部还原等式必须是不含专有名词的算式；隐含假设至少2个，每个只标注“可承受风险”或“致命风险”。每个字段必须改变、确认或否决预测/动作，或阻止错误；关键动作必须能指出字段支撑。耦合只记录 `changed/confirmed/rejected/unrelated`，重大判断出现 `unrelated` 必须重做定义，不能编造联系。默认对用户不显示图中的框架名、过滤器标题和固定字段，只自然说明建议、为什么这样做、关键风险/假设、验证信号与停止条件。

紧凑路径只在对象/目标/状态清楚、命中已验证 RUNBOOK、低风险可逆、无纠正/异常、无未验证致命假设、无规则冲突且不需要新高成本/不可逆授权时成立；最低仍要恢复事实、动作、适配理由、硬门禁、回读与升级信号。任一异常无条件升级完整闭环；重新满足全部资格且动作稳定为同一 RUNBOOK 时才可降级，不设固定轮数。不可逆或无直接反馈任务改用承重假设、反例/最坏情形、选择权保留和承诺前否决信号，不强造试点。

## 跨 Skill 依赖顺序

同一任务确实跨域时，按以下关系自动衔接，不要求用户逐个点名：

```text
战略/方向问题：IP 决策系统
        ↓ 需要当前外部证据
LinkFox 调研
        ↓
SKU/选品/Listing/投流数据：商品运营
        ↓ 提供真实 SKU 事实和商业目标
内容脚本/素材/视频：内容系统
        ↓ 有达人合作需求
达人建联
        ↓ 真实结果
知识迭代记录与复盘

任何新资料或新方法 → 知识蒸馏 → 回写上述对应 Skill
```

依赖顺序不等于获得线上操作授权；每个 Skill 仍遵守自己的外部动作门禁。

## “千川”统一解释

在本知识库的运营与蒸馏语境中，`千川` 统一归入“付费投流/广告投放”概念，不建立千川独立 Skill：

- 千川素材策略 → 路由到 `tiktok-content-system` 的投流素材、钩子、差异化和 A/B；
- 千川投放/消耗/ROI/ECPM → 路由到 `tiktok-commerce-operations` 的广告数据诊断；
- 千川课程或视频 → 先由 `knowledge-distillation` 完整文字化，再提取可迁移的投流机制；
- 从千川迁移到 TikTok 时，只迁移机制，不迁移平台按钮、固定阈值、审核漏洞或算法断言；当前 TikTok/GMV Max 事实需要重新核实。
