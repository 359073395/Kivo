# 蒸馏知识自动调用与 Skill 同步协议

本协议是用户于 2026-08-29 明确确认的长期规则：用户只需描述工作目标，不需要再次提醒 AI“查知识库”“使用哪个 Skill”或“套用刚蒸馏的方法”。七个主 Skill 必须主动检索与当前情境相关的已批准知识，并把它编入分析、执行、检查和复盘。

## 一、自动调用不等于全部加载

每次任务只读取与当前目标、模式、SKU、市场和阶段有关的内容：

1. 当前用户指令与当前项目事实；
2. `活动规则总表.md` 中适用的 `active` / `active_project` 规则；
3. 当前主 Skill 及其被路由到的 RUNBOOK；
4. 与该模式绑定的活动方法卡和已复盘知识；
5. 当前官方/平台事实或外部研究证据；
6. 候选知识与来源正文，仅在需要提出测试假设或追溯时读取。

不得为了“自动”而一次加载整个知识库，也不得把无关课程观点混入当前任务。

## 二、具体问题分析门禁

AI 必须从用户这一次的具体问题出发，不能从“我有哪些方法”出发。无需用户提醒，先在内部确定：

- 用户原问题和真正要得到的结果；
- 当前对象：店铺、SKU、视频、达人、账号、项目或知识来源；
- 市场、阶段、时间范围和当前状态；
- 已有事实、数据、素材和用户已确认信息；
- 关键未知、约束、风险和最可能的当前瓶颈；
- 哪个判断或动作会真正改变结果。

然后只调用能解释或解决该问题的规则和方法。一个方法与当前问题没有直接关系，就不应因为它“存在于知识库”而出现在答案中。

交付必须先回答用户的具体问题，再给针对当前对象的判断、优先动作、依据、成功信号和停止条件。禁止：

- 只复述通用知识、课程框架或完整方法清单；
- 把多个方法机械堆到同一个任务；
- 让用户先选 Skill、提醒查知识库或重新解释已经明确的信息；
- 在有足够信息时反复提问；非关键缺口采用清楚标注的合理假设继续，只有会实质改变结论的关键缺口才询问。

## 三、不同状态怎样使用

| 状态 | 自动使用方式 |
|---|---|
| `active` | 在适用触发条件成立时直接进入分析和执行，不需要用户再次点名 |
| `active_project` | 只在对应项目、店铺、SKU、批次或时间范围内自动使用 |
| `candidate` / `candidate_test` | 只用于生成清楚标注的假设或 A/B，不作为默认结论 |
| `needs_reconfirm` | 在依赖该结论前先核实；无法核实时停止该分支 |
| `deprecated` / `archived` | 不参与自动执行，只用于追溯替代关系 |

来源逐字稿、课程正文和作者观点没有因为被蒸馏就自动获得活动权限。用户明确确认的是经过筛选、冲突处理和边界化后的方法，而不是来源中的每一句话。

## 四、每次业务任务的自动运行顺序

1. 把用户的具体问题整理为“结果、对象、市场/阶段、事实、未知、瓶颈和风险”，不要求用户补一句“调用知识库”。
2. 根据这个具体问题自动选择一个主 Skill；任务跨域时按依赖增加其他 Skill，不让用户先选名称。
3. 读取活动规则和当前模式 RUNBOOK，并按触发词/问题检索关联方法卡。
4. 只要问题包含判断或选择，自动调用 `ip-commerce-decision-system/references/deep-reasoning-protocol.md`，在内部同步形成：矛盾阶段、主要矛盾、节奏；无专有名词的还原等式、杠杆变量、边界常量，以及至少2个只标注“可承受风险/致命风险”的隐含假设。两套检查无先后。默认交付不显示课程/框架名称、过滤器标题或固定模板，只把结论翻译成“为什么这样做、依据、风险/假设、验证信号与停止条件”；仅在用户明确要求框架、来源或审计时展示内部结构。非惯例、高影响、创新、旧方法反复失败或承重假设不稳时，再展开完整融合闭环并把最新反馈作为下一轮第一输入；常规低风险决策使用紧凑版本。
5. 只把适用方法转成当前对象的步骤、判断信号、检查清单和停止条件；不机械复述课程结论。
6. 先过事实、身份、时效、合规、权限和真实素材门禁，再执行最小授权动作。
7. 方法 ID、内部框架名和被拒绝路线默认写入项目/复盘供追溯，不在普通交付中堆砌；对用户只呈现会影响当前决定的关键未知项和原因。用户明确要求审计时再展示这些标识。
8. 任何反馈或异常一出现，立即把“预期—动作—实际—外部变量—反例—哪一层被改写—下一轮”写入项目摘要或复盘；不得等到所谓最终结果才纠偏。
9. 若结果被用户明确批准或在真实批次中验证通过，把它编译成行为回归用例；下次任务开始前先验证“知识库根定位—项目恢复—方法选择—审核门—停止条件”，不能只验证 Markdown、JSON 和目录结构。
10. 对有测试后批量门禁的流程，读取 `最新批量批准标准索引.md`：只有最后一次用户明确批准批量执行的同范围版本进入活动路线；更新但未获批批量的测试结果保持候选。不得根据文件修改时间、AI 自评或单次样片通过擅自覆盖。

自动分析不扩大外部权限。发送、发布、上传、改线上 Listing、创建广告、改佣金、付款、寄样和批量高成本生成，仍须当前任务明确授权。

## 五、以后每次知识蒸馏的固定闭环

完成来源文字化和知识提炼后，必须继续完成以下动作，不能只留下总结文件：

1. **查重**：搜索已有活动规则、主 Skill、RUNBOOK、方法卡和近义资产。
2. **编译**：把可复用内容写成触发、范围、输入、执行、判断、检查、停止和反馈齐全的方法单元。
3. **定状态**：区分用户确认、已验证、候选、待核实、冲突和淘汰项。
4. **冲突确认**：若冲突会改变结论、适用范围或 Skill 执行，且当前用户指令/活动权威不能直接裁决，先向用户列出冲突双方、来源、影响和选项；得到确认前不完成该冲突部分的总结或同步。非冲突部分可以继续。
5. **定路由**：为每个方法指定现有主 Skill 与具体模式；同类职责优先更新现有 Skill，不新建近义入口。
6. **同步执行层**：
   - 用户已明确要求长期/自动使用，且范围清楚、无未解冲突的方法，同步到对应 Skill 的活动方法路由；
   - 有真实复用或回测支持的方法，同步到对应 Skill；
   - 只有来源观点、没有用户确认或验证的方法，留在候选层，只给出验证方案，不进入自动执行。
7. **新 Skill 门禁**：只有现有七个主 Skill 都无法合理承接，且流程稳定、会重复、有独立输入输出和停止条件时，才提出新增 Skill；不能因一篇资料或一个术语就新建。
8. **验证**：运行受影响 Skill 的结构与行为检查、活动规则面、Markdown/JSON、manifest；记录替代关系和日志。
9. **备份**：只有实质更新且验证通过后才生成便携备份。

蒸馏报告必须明确写出三类结果：已同步到哪些 Skill、哪些仍是候选、哪些被拒绝/淘汰及原因。

## 六、成功经验怎样进入执行层

用户原话、任务状态和实际产物必须分层保存：

1. **证据层**：来源卡或对话证据稿保留任务 ID、时间、用户批准/拒绝原话和可核验结果。
2. **方法层**：明确当前生效版本、适用范围、必要输入、已验证参数、失败路线、替代关系和停止条件。
3. **执行层**：更新对应 Skill/RUNBOOK、状态字段与自动路由；缺上游中间产物时自动补齐，不让用户选择内部步骤。
4. **回归层**：至少覆盖从知识库外的工作目录启动、恢复正确任务、已有批准不重复询问、缺人物自动准备、缺真实商品停止、额度不足停止等真实分支。
5. **版本层**：若流程有样片/测试门，批量批准时生成标准 ID 并更新 `最新批量批准标准索引.md`；同范围旧标准标记被替代，未获批测试稿保留为候选。后续自动读取活动指针，不再要求用户重述。

没有完成这四层，不能把“已经总结”当作“以后会正确执行”。

## 七、冲突和停止条件

- 新方法与用户当前规则冲突且当前规则已明确覆盖时，以当前用户规则为准，记录裁决，不重复询问。
- 不同活动规则、多个同等级来源或适用范围之间发生无法直接裁决的冲突时，先询问用户；答复前将该部分标为 `conflict_pending_user`，不得写成最终总结或同步到 Skill。
- 平台算法、广告公式、价格、时效数据和工具能力可能变化，使用前按当前证据核实。
- 无法判断适用 Skill、范围会明显扩大、会覆盖用户原规则、或需要高影响合并/删除时，停止结构变更并向用户确认。
- 自动检索没有找到适用知识时，按主 Skill 的基本流程执行，并把缺口登记为新蒸馏/研究问题；不得编造“知识库已有规则”。

## 八、规则编译与运行时效果

- 蒸馏结论拟进入活动规则前，必须通过 `规则权威与变更协议.md` 的活动规则编译门；能被现有规则吸收时只更新现有入口，不增加近义规则。
- 已进入执行层的固定字段必须留下可观察效果：`changed`、`confirmed`、`rejected`、`prevented_error` 或 `no_material_effect`；不得保存隐藏思维。
- 原始效果信号存放在机器本地 `<productionWorkRoot>/rule-effects/pending/`，不进入便携 manifest；聚合后的跨任务模式、规则审查候选和实质变化才写入 `辅助/规则效果/` 与主日志。
- `no_material_effect` 只能触发路由/定义重查或规则审查，不能自动停用活动规则。只有用户批准或真实结果验证才能晋升方法；规则合并、替代、降级和停用仍走权威协议。
