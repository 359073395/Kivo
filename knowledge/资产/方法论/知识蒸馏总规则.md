# 知识蒸馏总规则

本文件是整个本地知识库的蒸馏权威规则。专门入口是 `knowledge-distillation`；`knowledge-iteration` 负责摄入登记、维护、日志、归档和迁移。其他业务 Skill 和任何读取本库的 AI 都必须遵守本规则。

## 一、蒸馏的目的

蒸馏不是“把原文缩短”，而是把来源编译成以后能可靠调用的决策与执行单元。

一条合格的蒸馏结果必须回答：

1. 遇到什么情况触发；
2. 它适用于谁、什么任务和什么阶段；
3. 需要哪些输入和证据；
4. 应依据哪些经验或事实；
5. 按什么顺序执行；
6. 用什么信号判断正确或有效；
7. 如何检查结果；
8. 什么情况必须停止、降级或转人工；
9. 结果怎样反馈到规则和下一次任务。

因此：Skill 不是“AI 知道什么”，而是“遇到什么情况，AI 应依据哪些经验，怎样执行、判断、检查和停止”。

## 二、知识编译层级

```text
原始来源
→ 来源卡与可读性记录
→ 完整文字化稿
→ 事实/观点/推断/冲突拆分
→ 可复用知识单元
→ 方法卡与候选规则
→ 经验证的活动规则
→ Skill 执行流程
→ 项目真实结果
→ 复盘与规则更新候选
```

任何来源都不能直接越过证据与验证层，静默变成长期活动规则。

## 三、来源登记

处理前必须为每个来源记录：

- 来源 ID；
- 标题与作者/发布者；
- 文件路径或 URL；
- 来源类型：对话、网页、视频、音频、文档、表格、图片、书籍或项目结果；
- 获取或访问日期；
- 时效范围；
- 是否完整可读；
- 处理状态；
- 权利、隐私和可复用边界；
- 不能读取的部分。

推荐状态：

- `registered`：已登记，未处理；
- `processing`：正在处理；
- `partial`：只处理了部分内容；
- `distilled`：完整范围已蒸馏；
- `blocked`：需要登录、权限、附件或用户输入；
- `unreadable`：损坏或当前工具不支持；
- `superseded`：已被更新来源替代，但保留追溯。

禁止把 `registered`、`partial` 或 `blocked` 写成“已经完整学习”。

## 四、完整性规则

- 网页应读取正文与必要子页，保留 URL、访问日期和页面范围。
- 视频/音频必须先转成覆盖完整时长、带时间戳的 Markdown 逐字稿；重要屏幕文字、操作步骤和纯画面信息另做 OCR 或文字描述。抽帧或片段只能用于预览，不能冒充完整学习。
- PDF 必须先转成覆盖全部页的 Markdown 文字稿：文字型 PDF 逐页提取，扫描型或混合型 PDF 对无文本页做 OCR；保留页码、标题层级、表格、列表、脚注、图表说明和无法识别标记。
- DOCX/PPTX 转成保留标题、正文、表格、讲者备注与关键图示说明的 Markdown；图片资料使用 OCR 并标记不确定文字。
- 书籍和长文按章节建立处理清单，记录覆盖率和未读部分。
- 表格保留工作表、表头、单位、公式口径和缺失字段。
- 无法访问时登记阻断原因，不能根据标题、封面或记忆补造内容。
- 只完成抽样、局部转录或部分 OCR 时，来源状态只能是 `partial`，不能进入完整蒸馏门禁。

## 五、信息类型必须拆分

每个知识点至少标记为以下一种：

- `verified_fact`：有证据的事实；
- `user_confirmed_rule`：用户明确确认的长期规则；
- `user_preference`：用户偏好；
- `source_view`：作者或来源观点；
- `agent_inference`：AI 推断；
- `hypothesis`：待验证假设；
- `conflict`：来源之间或新旧规则冲突；
- `unknown`：证据缺失。

`unknown` 不等于 0，不等于否，也不能通过硬门禁。

### 字段级来源三轴

任何会进入方法卡、规则、案例结论或来源锚点的关键字段，必须把以下三件事分开记录：

- `provenance`：该字段来自原著核心、用户确认、真实结果、来源观点、现代编译、AI 迁移或其他哪一层；
- `verification`：尚未定位、OCR 定位、原扫描已回看、直接用户原话已核对等核验程度；
- `governanceStatus`：仅作证据、候选、待确认、活动或已废弃等执行权。

来源核验通过不自动赋予执行权；用户规则也不得冒充作者原意；现代编译没有页码时 `verification` 可写 `not_applicable`，不能伪造锚点。扫描资料同时记录 OCR 页标 `ocrPageMarkers` 和原书印刷页码 `printedPages`；确实不存在时允许 `null`，不得猜填。多个锚点必须逐个记录，不能把一整组页码共用一个模糊状态。

## 六、查重、时效与冲突

写入前搜索标题、别名、关键词、适用场景和正文。

- 相同概念优先更新现有权威页，不新建近义重复页。
- 新来源不得直接覆盖旧来源；先比较日期、证据、范围和适用条件。
- 当前用户确认和当前项目真实结果优先于旧课程观点。
- 平台规则、价格、市场数据、软件能力和账号状态属于易变信息，使用前重新验证。
- 冲突无法解决时并列保存，说明各自适用条件和需要补的证据。
- 若冲突会改变最终总结、活动方法或 Skill 执行，且当前用户指令/活动权威不能直接裁决，必须先向用户展示冲突双方、来源、影响和可选处理；答复前状态为 `conflict_pending_user`，不得完成该冲突部分的最终总结或自动同步。已有明确高优先级规则能直接裁决时，按其处理并记录裁决依据。

## 七、知识单元标准结构

每个可复用知识单元应尽量包含：

```text
ID：
标题：
状态：候选 / 已验证 / 活动 / 已废弃
版本与日期：
来源与证据：
知识类型：
触发情境：
适用范围：
不适用范围：
最低输入：
硬门禁：
执行步骤：
判断标准：
检查清单：
停止/转人工条件：
例外与反例：
输出格式：
反馈字段：
关联 Skill/项目：
```

只有“结论”而没有触发、检查和停止条件的内容，只能作为参考知识，不能直接晋升为 Skill 规则。

## 八、规则生命周期

```text
source_note
→ candidate_rule
→ reviewed_rule
→ validated_rule
→ active_rule
→ deprecated_rule
→ archived_rule
```

- 一次聊天、一本书或一个案例默认只能生成候选规则。
- 用户明确确认的操作偏好可以直接成为活动偏好，但仍需记录范围和日期。
- 业务方法应通过复用、回测或真实项目结果验证。
- AI 不得未经用户确认自动扩大适用范围。
- 被新规则替代的旧规则进入归档，保留替代原因和恢复条件。

## 九、Skill 晋升门禁

知识只有满足以下条件才适合写成 Skill：

- 有清晰触发语句和任务边界；
- 有稳定输入和输出；
- 有可重复执行步骤；
- 有判断、检查与停止条件；
- 与现有 Skill 没有无法解释的重复；
- 外部工具依赖和授权边界明确；
- 失败时知道如何降级或暂停；
- 至少有一个真实例子或验证方案。

Skill 的正文保持路由和核心规则简洁；长知识、脚本、模板和示例进入 `references/`、`scripts/` 和 `assets/`。

蒸馏资料时先确定目标：工具书、操作教程和成熟流程优先提炼 `what they do`；非工具书、访谈和思想材料优先提炼 `how they think`。蒸馏个人技能时必须从真实任务开始，通过用户反馈校准，最后再把共识整理成 Skill，并在每次真实使用后继续收集反馈。

## 十、存储规则

知识库内保存：

- Skill、规则、知识单元、方法卡；
- 来源索引、最终清洗后的完整 Markdown 文字稿和轻量可复查证据；
- 视频/音频逐字稿、PDF/文档全文稿、网页正文稿、OCR 文字稿和规范化表格；
- 项目摘要、manifest 和最终复盘。

知识库外保存：

- 原视频、原音频、原 PDF/大型文档、抽帧和临时转录/OCR 缓存；
- B-roll、HeyGen 底片、ChatCut/CapCut 工程和成片；
- 临时下载、浏览器缓存、外部工具原始输出。

原始大文件在知识库外保留时，知识库记录其路径、哈希、状态和恢复条件；最终文字稿必须留在知识库内。未经用户明确授权，不因完成文字化而删除原件。

禁止保存密码、Cookie、API Key、OAuth Token 和登录状态。

## 十一、蒸馏完成门禁

只有同时满足以下条件才可标记 `distilled`：

- 来源范围和完整性已记录；
- 视频/音频/PDF/文档/网页等来源已生成完整文字稿，或明确说明该来源本身就是完整文本；
- 最终文字稿存入知识库，原始大文件与临时缓存遵守内外存储边界；
- 事实、观点、推断、冲突和未知已拆分；
- 完成查重与时效检查；
- 至少更新一个权威知识资产；
- 触发、执行、判断、检查和停止条件已补齐；
- 未读、不可读和证据缺口已进入队列；
- 更新文件和关键判断已写入知识库日志；
- 没有把未读取内容声称为已学习。

## 十二、反馈闭环

每次真实任务结束记录：

- 原假设与预期；
- 实际执行；
- 结果与指标；
- 成功原因；
- 失败和外部变量；
- 反例；
- 是否形成候选规则；
- 是否需要用户批准升级规则。

固定闭环：

```text
输入 → 消化 → 输出 → 真实反馈 → 日志 → 候选更新 → 验证 → 活动规则
```
