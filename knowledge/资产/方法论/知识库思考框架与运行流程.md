# 本地知识库思考框架与运行流程

本文件说明 AI 在任何新任务中怎样自动恢复 `D:\Knowledge` 的规则、方法和项目状态。它不是一篇理论介绍，而是当前活动执行流程。知识库迁移到新电脑后，只要新环境能定位 `knowledge-base.json` 和根 `AGENTS.md`，这套逻辑不依赖旧对话记忆。

## 一、先确定什么能指挥执行

同一问题出现多种说法时，依次服从：

1. 用户当前任务中的明确要求；
2. 当前项目里用户最后批准的批量标准和已验证事实；
3. `资产/规则/活动规则总表.md` 中范围匹配的活动规则；
4. 已验证 RUNBOOK、已审核方法卡和主 Skill；
5. 候选方法、来源观点、课程、旧对话和 AI 方案。

低层证据不能覆盖高层规则。助手回复、课程讲法、名人案例和旧方案都不能自行升级为长期规则；会改变执行且无法按上述顺序解决的冲突，停止升级并询问用户。

价值目标、人生使命和风险偏好由用户决定。AI 可以检查方案是否与用户已给目标一致，不能借课程人物或哲学叙事替用户选择目标。

## 二、新任务启动

```text
定位知识库根与 AGENTS.md
  → 读取活动规则、当前项目摘要和最近一次真实反馈
  → 判断本次对象、目标、阶段、市场、期限、权限与不可逆风险
  → 自动选择一个主 Skill；需要时衔接其他 Skill
  → 只读取与本问题相关的知识和证据
```

七个主入口是：知识蒸馏、知识迭代、TikTok 商品运营、TikTok 内容系统、达人建联、IP/电商决策系统、LinkFox 调研。用户只需要描述目标，不需要点名 Skill。

主 Skill 路由后，再按问题性质选择思考入口：

| 问题类型 | 启动路径 | 最低要求 |
|---|---|---|
| 纯事实/知识 | 直接回答 | 标明当前事实、未知和来源等级；不强行展开框架 |
| 纯执行 | 已验证 RUNBOOK | 恢复项目状态、检查硬门禁、执行、回读；遇异常立即升级 |
| 含判断/选择 | 两道固定过滤器 | 先做紧凑资格检查；不合格即完整闭环 |
| 价值/情感/伦理 | 用户价值边界 | AI 只检查路线与目标、后果和风险是否一致，不替用户决定终局价值 |
| 混合问题 | 拆成事实、终局价值、实现手段 | 事实核验；价值归用户；手段进入判断或执行路径 |

价值拆分使用翻转判据：若把一组合理价值排序换成另一组会使方案排名翻转，这部分不是纯事实，必须由用户决定。已有明确价值可作为本轮边界常量；缺失且会实质改变结论时才询问，不把偏好藏进“客观最优”。

## 三、包含判断或选择时的固定思考层

两套固定检查读取同一批事实和最新反馈，在内部同步运转、没有先后：

| 内部检查 | 必须形成 |
|---|---|
| 《毛选》 | 矛盾阶段、主要矛盾、节奏 |
| 第一性原理 | 还原等式、杠杆变量、边界常量、至少2个带风险标签的隐含假设 |

第一性原理固定为三个检查点：

1. **还原等式**：剥离行业术语、历史惯例和竞品做法，写出不含专有名词、能表达结果关系的算式；
2. **变量定位**：指出当前波动最大且可干预的杠杆变量，以及本轮锁定、不讨论的边界常量；
3. **前提检验**：至少列出2个理所当然的承重假设，逐条只标注“可承受风险”或“致命风险”；极端反例和反馈信号放入共同验证设计，不增加固定检查点。

紧凑路径必须同时满足：对象、目标和状态清楚；命中活动且已验证的 RUNBOOK；动作低风险、可逆；没有用户纠正或回读异常；没有未验证的致命假设；没有活动规则冲突；不需要新的高成本或不可逆授权。任一条件不满足即走完整闭环。

紧凑路径也至少要恢复当前事实和最新反馈、执行当前动作、说明为何适配当前对象、检查硬门禁、回读结果并定义异常升级信号。只要仍包含判断，`IP-004` 三检查点就不能跳过；每个字段必须改变、确认或否决预测/动作，或阻止错误。全部字段都无实质影响时，重查任务分类或问题定义，不能补一张漂亮但无用的表。

紧凑路径一旦出现回读异常、用户纠正、假设被证伪、未预见异常、规则冲突或新高成本/不可逆授权需求，无条件升级完整闭环。完整闭环只有重新满足全部紧凑资格、且动作已经稳定为同一已验证 RUNBOOK 时才能降级；写明理由，不设机械轮数。

默认对用户不显示两套方法的名称、过滤器标题、还原等式或固定检查表。交付时把内部结论翻译成自然语言，只回答当前对象的建议、为什么这样做、关键依据和风险、怎样验证、何时停止或改向；只有用户明确要求查看框架、来源或审计底稿时，才展示内部结构。

## 四、认知与行动不能线性分工

```text
最新反馈或异常
  ↕ 问题的运动轨迹、当前阶段、矛盾双方与力量条件
  ↕ 底层等式、变量、约束和承重假设
  ↕ 主要矛盾与行动轮廓共同更新
  → 业务硬门禁内的最小判别性动作
  → 新反馈立即回灌全部判断
```

调查会改变拆解，拆解也会改变调查方向；抓住主要矛盾时方案应露出轮廓，方案必须反向说明自己作用于哪个阶段、矛盾和杠杆。反馈不是最后复盘才使用，而是下一轮的第一输入。

两道过滤器的可观察耦合只允许四种结果：`changed`、`confirmed`、`rejected`、`unrelated`。前一道判断改变/确认/否决了后一道的变量、假设、阶段或排序时如实记录；不能为了证明“同步”编造联系。事实或纯执行问题出现 `unrelated` 可以退出完整模式；重大判断出现 `unrelated` 说明当前问题定义没有闭合，必须重做。

## 五、业务 Skill 把判断变成可回读动作

内部每轮必须明确，面向用户只保留会影响当前决定的部分：

- 当前判断和真正未知；
- 作用的主要矛盾与结构杠杆；
- 最小授权动作、负责人和依赖；
- 基线、成功信号、失败信号、最早回读时间；
- 费用、权限、真实素材、合规、现金流和停止门禁；
- 出现什么反馈时要立即重判，而不是继续批量。

“最小”不是固定金额、样本数或课程数字，而是当前风险下能区分不同判断的最低成本。样片、单 SKU、小流量、竞品证据、用户反馈或表格回读都可以是探针，但不能越过外部动作授权。

一次性、不可逆或无法取得直接反馈的决策不强行制造试点。改走：硬门禁 → 承重假设审计 → 反例与最坏情形推演 → 可逆准备和选择权保留 → 在承诺前预写否决/延迟信号。必要时补独立证据或专业意见；最终不可逆承诺由用户确认。

## 六、一次任务怎样沉淀成长期能力

```text
事前判断 → 动作 → 实际反馈 → 哪个阶段/假设/规则被修正 → 下一轮
```

单次成功或失败只形成候选经验。只有用户明确确认，或在边界一致的真实任务中复用验证，并完成冲突检查后，才同步到活动规则、对应主 Skill 或 RUNBOOK。相同范围内，用户最后批准并要求批量执行的版本是当前标准；旧版本标记替代关系，不能与新版本同时生效。

每天的规则审计只把用户原话当作潜在长期规则来源；助手回复、课程、附件、截图和旧 AI 方案只能提供证据或候选。只有发生实质变更且结构、链接、JSON、Skill 和 manifest 验证通过时才生成新便携备份；无变化不制造版本噪音。

## 七、新资料怎样进入知识库

视频、音频、PDF、网页、图片和书籍先由知识蒸馏 Skill 处理：

```text
登记来源与哈希
  → 视频/音频完整转录；PDF/PPT/图片文字化与必要 OCR
  → 错字、首尾、覆盖率、结构和来源定位检查
  → 长来源分块，逐块提取框架/原则/案例/反例边界/术语
  → 区分用户规则、已验证事实、候选方法、来源观点和争议
  → 检查与现有规则/Skill 的重复与冲突
  → 只把用户确认或真实验证的方法同步到对应现有 Skill
  → 更新项目、队列、日志、manifest；实质变更通过验证后备份
```

原视频、抽帧、OCR 临时文件和剪辑工程留在外部工作目录；知识库只保存最终 Markdown 文字稿、可执行知识、来源卡、项目摘要、日志、manifest 和复盘。

## 八、默认停止条件

遇到以下情况停止扩张或批量：关键身份/对象未知；真实商品或数据缺失；活动规则冲突未解；致命假设没有先行验证；费用、发布、发送、删除或其他外部动作没有授权；结果已触发预设失败/漂移线；当前证据无法区分竞争判断。

## 九、一份完整决策交付的最小结构

```text
当前事实与未知
建议做什么
为什么现在这样做：关键事实｜因果依据｜必要风险/假设
怎样执行：优先动作｜负责人｜门禁
怎样验证：基线｜成功/失败/重判信号｜回读时间
何时停止或改向：实际结果｜被修正的判断｜下一轮
```

上述是普通用户回答的最小结构，默认不出现内部方法名称或检查表。详细路由见 `资产/规则/七个主Skill自动运营总图.md`；规则权威见 `资产/规则/规则权威与变更协议.md`；内部联合协议见 `资产/方法论/第一性原理决策系统/01_联合决策总协议.md`。
