# 大李 AI 知识库：本地知识库与蒸馏方法

## 状态与范围

- 状态：`partial`，只覆盖与本地知识库、Skill、蒸馏、视频文字化直接相关的已读页面。
- 来源卡：`资源/来源索引/2026-08-21_大李AI知识库_蒸馏与本地知识库来源卡.md`。
- 信息类型：以下“来源方法”是 `source_view`；“本库执行决定”包含用户明确确认的 `user_confirmed_rule`。

## 一、本地知识库的长期价值

来源方法认为：资料少、只想快速开始时可以使用平台知识库；一旦把知识视为长期资产，本地文件夹在控制权和迁移上更有优势。平台的解析、切片、召回和检索方式由平台决定，而本地文件可让 Agent 更直接地读取、整理和维护。未来更换 Agent 或浏览工具时，本地文件也更容易整体迁移。

本库执行决定：`D:\Knowledge` 是可搬家的知识与工作大脑。它不依赖 Obsidian、IMA 或某个云端平台；复制整个目录并恢复 Skill 注册后，可以继续使用相同规则、文字稿、知识和项目摘要。

## 二、知识库首先给 AI 使用

来源方法把 Agent 视为知识库的主要使用者。知识的价值不在于人工维护漂亮图谱，而在于 Agent 能否在需要时找到、组合并用于任务。Markdown 既方便 AI 读取，也允许 Obsidian 或其他编辑器作为可选浏览器。

本库执行决定：所有入口都以 `AGENTS.md`、`knowledge-base.json` 和 `skill/<name>/SKILL.md` 为机器可读主线；人工浏览界面只是辅助。

## 三、Skill 是工作手册，不是知识摘要

来源方法将 Skill 定义为可重复使用的工作方法。`name` 与 `description` 负责让 Agent 判断何时使用，正文负责先后顺序、参考资料、工具、检查和必须停下来的情况。复杂 Skill 可以把长资料、脚本和模板拆到独立目录，以减少每次加载的上下文。

本库执行标准：Skill 至少回答触发情境、输入/证据、执行、判断、检查、停止/转人工、异常恢复、输出和反馈。只含结论的资料留在知识资产层，不能直接冒充 Skill。

## 四、资料蒸馏的两种核心目标

来源方法把资料蒸馏分成：

- `what they do`：提炼作者怎么做、步骤是什么、哪些条件下适用；
- `how they think`：提炼作者看问题时关注哪些变量、如何判断因果、冲突时怎样取舍。

用户读过材料时，可以把自己的理解用于校准；用户未读或不熟时可以先生成证据驱动的初稿，但应回到原文核对关键结论。一本书或长访谈可以拆出多个边界清楚的 Skill，而不是一个万能 Skill。

## 五、个人技能蒸馏的共创四步法

来源方法：

1. 用一个明确、真实的工作目标让 AI 先做一次；
2. 用户反复指出哪里不对、原因和合格标准，把隐性经验变成显性规则；
3. 把完整工作过程整理成 Skill，固定目标、输入、步骤、判断、工具、异常和输出；
4. 每次真实使用后继续收集反馈，删重复、补边界、修规则。

本库补充门禁：一次性要求不能自动升级为长期规则；新规则默认是候选，经过用户确认、复用、回测或真实结果后再升级。

## 六、先文字化，后蒸馏

来源的“视频转逐字稿”流程强调：长视频先在本机抽取音频，用本地 Whisper 完整转写为带时间戳的 Markdown，自然段可合并但不能删改原意；稿件记录原文件、语言、模型、时长和生成时间。视频要蒸馏时，先取得文字稿。

用户把这一原则扩展并确认为本库活动规则：

```text
视频/音频
→ 覆盖完整时长的带时间戳逐字稿
→ 补重要屏幕文字和纯画面信息
→ 保存最终 Markdown 到 Knowledge
→ 再蒸馏

PDF/文档
→ 全文提取；扫描页做 OCR
→ 保留页码、结构、表格、脚注和图表说明
→ 保存最终 Markdown 到 Knowledge
→ 再蒸馏
```

原视频、原音频、原 PDF、抽帧和临时转录/OCR 缓存在外部本地工作目录。最终文字稿是可搜索、可迁移的知识资产，必须在知识库内。

## 七、两个系统入口必须分开

- `knowledge-distillation`：文字化来源，蒸馏资料或个人技能，生成/迭代候选 Skill，并执行蒸馏验收。
- `knowledge-iteration`：登记来源、查重、维护权威页、更新日志/队列/manifest、会话交接、归档和迁移。

这样可避免“只建来源卡和目录却没有真正学习内容”，也避免把维护型动作误认为蒸馏完成。

## 八、检查与停止

- 视频未覆盖全时长、PDF 未覆盖全部页、网页必要子页未读取时，只能标记 `partial`。
- 无法访问、损坏、权限不足或关键内容无法识别时，记录 `blocked`/`unreadable`，不能从标题补造。
- 事实、作者观点、AI 推断、用户规则、冲突和未知必须分开。
- 关键结论应能回到页码、时间戳、章节或 URL 核对。
- 尊重授权与版权：学习和提炼方法不等于可以整库搬运或重新打包发布。
