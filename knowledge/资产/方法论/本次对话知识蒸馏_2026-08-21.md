# 本次对话知识蒸馏：本地知识库与 Skill 系统

## 蒸馏状态

- 来源：2026-08-21 本地知识库搭建对话。
- 状态：对话决定已蒸馏；飞书网页已读取与本地知识库/Skill/蒸馏直接相关的页面，整库仍为 `partial`；抖音视频仍为 `blocked`。
- 知识类型：用户确认规则、已验证系统事实、候选工作规则。

## 一、用户的核心目标

建立一个不依赖 Obsidian 的本地个人知识库。完整备份一个文件夹后，可以在新电脑继续使用同一套 Skill、规则、方法、项目摘要和复盘；大型素材和账号登录不随知识库自动迁移。

## 二、知识库的唯一边界

`Knowledge` 内只保存：

- Skill；
- 规则和判断方法；
- 视频/音频最终逐字稿、PDF/文档全文稿、网页正文稿和 OCR 文字稿；
- 已蒸馏知识；
- 项目摘要和会话交接；
- manifest 与最终复盘；
- 恢复、验证和轻量配置说明。

单独本地生产目录保存：

- 原视频、原音频、原 PDF/大型文档、抽帧和临时转录/OCR 缓存；
- 产品图、B-roll 和其他素材；
- HeyGen 底片；
- ChatCut/CapCut 工程；
- 最终成片和临时下载；
- 外部工具原始结果。

推论：备份知识库能搬走“大脑”，其中包含最终文字稿；但不能自动搬走原始大文件、“生产车间”和“工具登录”。

用户后续明确修正规则：蒸馏必须“先文字化、后蒸馏”。视频和音频需转成完整文字稿，PDF/文档需转成全文 Markdown 稿并存入知识库，以减少主库对大型二进制文件的依赖。只有原件和临时转换缓存留在外部目录。

## 三、目录设计

七个知识库主目录：

| 目录 | 职责 |
|---|---|
| `项目/` | 项目摘要、会话交接、状态和下一步 |
| `资产/` | 已蒸馏知识、方法、报告和复盘 |
| `资源/` | 来源索引、轻量证据和待处理来源 |
| `辅助/` | 配置、迁移、清单、队列、日志和维护 |
| `灵感/` | 待验证选题、观点、案例和假设 |
| `skill/` | 七个可执行工作系统 |
| `归档/` | 被替代的 Skill、规则和项目历史 |

## 四、Skill 的定义

用户确认的定义：

> Skill 不是“我知道什么”，而是“遇到什么情况，AI 应依据哪些经验，怎样执行、判断、检查和停止”。

由此得到 Skill 的最小结构：

```text
触发情境
→ 输入与证据
→ 硬门禁
→ 执行步骤
→ 判断标准
→ 验证检查
→ 停止/转人工条件
→ 结果回写与复盘
```

## 五、七个活动 Skill

### `knowledge-distillation`

专门负责资料文字化、书籍/课程/访谈/网页蒸馏、个人技能共创蒸馏、候选 Skill 生成和真实使用后的迭代。视频、音频、PDF、文档等必须先形成完整 Markdown 文字稿。

### `knowledge-iteration`

负责来源登记、查重、知识维护、日志、队列、会话交接、归档、manifest、迁移和复盘；不再和专门蒸馏职责混用。

### `tiktok-commerce-operations`

合并店小秘周更、SKU/飞书、Listing 和选品。用户以后只需描述商品运营目标，不必选择旧入口。

### `tiktok-content-system`

合并涨粉、内容准备、纯 HeyGen、数字人 B-roll 和 ChatCut。Seedance 当前归档停用。

### `tiktok-creator-outreach`

负责达人导表、清洗、证据评分、深度复核、未发送草稿和结果复盘。

### `ip-commerce-decision-system`

把个人 IP、带货和书籍/课程知识改造成具有执行、判断和停止条件的决策系统。

### `linkfox-research`

保留为外部跨境数据和调研证据层，不替本地决策系统做最终决定。

## 七、最新视频生产规则

普通“做数字人口播”：

```text
纯 HeyGen 模式
```

“做带 B-roll 的完整带货视频”：

```text
核验产品事实
→ 高保真原创文案
→ GPT 生成人物手持真实产品图
→ 用户提供最终语音
→ HeyGen 生成对口型底片
→ 收集/生成合规 B-roll
→ ChatCut 覆盖混剪
→ 导出与验证
```

锁定规则：用户最终语音是唯一主时间轴。锁定后不得擅自剪切、重排、替换、重生成、变速或改变停顿。

ChatCut 有两个分支：

- 可编辑 A-roll：普通口播可在不改变事实和意图的前提下清理停顿、口误和冗余。
- 锁定音频覆盖混剪：B-roll 只能覆盖画面，主音频必须连续。

对标仿写默认高保真结构镜像：对齐时长、段落、句数、钩子、信息密度、痛点/卖点顺序、情绪曲线、CTA 和镜头功能，但不得逐句照抄。

纯 BGM 只有在既无可懂人声、又无有意义销售屏幕文字时才可跳过；音频不清进入人工复核。

## 八、商品运营最新规则

- Flash Deal 使用每店当前活动页面下载的原始模板。
- 当前用户规则是直接填写原始 `Flash Deal.xlsx`。
- 默认不创建 `Flash Deal_已填写.xlsx`、备份副本或单独审计表。
- 仍必须在写入前验证店铺、模板、SKU、product ID 和价格，在写入后重新打开原路径验证。
- 店铺模板和 product ID 禁止跨店复用。
- `unknown`、空白和冲突不能当成 0。
- 清仓/下架、Npcs 冲突、同 product ID 不同变体价和缺失价格必须停止相应条目。

## 九、达人建联规则

- `unknown` 不等于 0，不重新分配未知分项权重。
- 事实、推断和待人工核验分列。
- 只生成 `pending_review` / `NOT_SENT` 草稿。
- 发送、寄样、改佣金、报价、授权和对外承诺都需要当前任务明确批准。
- A/B 必须在有足够真实结果证据后使用，不能把任意两个草稿提前命名为 A/B 测试。
- 达人建联结果需要回填回复、寄样、出片、点击、订单和 GMV 才能校准模型。

## 十、IP 与电商决策原则

- 个人 IP 的核心资产是人的信任和长期价值。
- 带货视频的核心资产是产品需求和成交效率。
- 选择方法前先定义情境、目标、时间范围、事实、未知和不可逆风险。
- 先通过硬门禁，再比较偏好和评分。
- 每个建议必须包含执行步骤、成功信号、失败/停止条件和什么证据会改变决定。
- 单次结果形成候选规则；复用、回测或用户确认后才能升级。

## 十一、迁移与新对话

- 完整复制知识库后运行 manifest 验证和恢复脚本。
- 恢复脚本把七个主 Skill 注册到 Codex 用户 Skill 目录。
- 重启 Codex并打开新对话后，Skill 才会使用新的发现清单。
- 其他 AI 可以读取 `START-HERE.md`、`AGENTS.md` 和对应 `SKILL.md`；能否自动调用外部功能取决于该软件。
- 外部软件、插件、账号、API 和大型素材不随知识库自动恢复。
