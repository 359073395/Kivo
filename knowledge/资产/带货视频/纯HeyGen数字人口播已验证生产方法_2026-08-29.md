# 纯 HeyGen 数字人口播已验证生产方法

- 方法 ID：`M-CNT-PURE-HEYGEN-001`
- 状态：`active`
- 当前版本：`2026-09-06-exact-remote-input-binding`
- 当前标准 ID：`STD-CNT-PURE-HEYGEN-20260827-01`
- 路由：`tiktok-content-system / pure_heygen`
- 证据：[HeyGen 生产经验对话来源卡](../../资源/来源索引/2026-08-29_HeyGen生产经验对话来源卡.md)、[商品人物图卖点、人群、光影、透视与人体工学规则来源卡](../../资源/来源索引/2026-09-06_商品人物图卖点人群光影透视人体工学规则来源卡.md)、[批准图与远端输入强绑定来源卡](../../资源/来源索引/2026-09-06_HeyGen批准图远端输入强绑定规则来源卡.md)
- 活动规则：`SYS-010`、`CNT-005` 至 `CNT-012`

## 解决什么问题

当用户要求纯 HeyGen 商品口播或续跑已有批次时，自动找到正确知识库和项目状态，复用已经通过用户批准与真实批次验证的方法。用户不需要再次解释人物要拿真实商品、人物要随 SKU 改变、画面要有印尼本地真实感、720p 更自然，也不需要替 AI 选择内部制作路线。

## 必要输入

每个 SKU 至少需要：

- 可核验的当前店铺/SKU 事实、真实卖点、使用方式与目标受众；
- 当前 SKU 的真实白底/透明商品图；
- 审核文案或已锁定音频，并有精确文件映射；
- 素材权利、声音/人物同意与生成政策门禁；
- 外部生产目录与可恢复的 `ACTIVE_TASK.json`，或足以首次建立状态的执行表。

缺真实商品、事实或审核文案/锁定音频时停止对应 SKU；不得用相似商品、空手人物或 AI 猜测替代。

## 决策与执行

1. **定位知识库**：当前路径上级 → 已加载 Skill 的真实目标路径上级 → `KNOWLEDGE_BASE_ROOT` → 仅在标记存在时用 `D:\Knowledge`。
2. **恢复项目**：优先用户明确路径；否则读取进行中项目摘要与 `productionWorkRoot` 下 `ACTIVE_TASK.json`。只接受精确或唯一可证明的近似目录，不新建近重复树。
3. **读取批准状态**：样片批准只通过测试门；只有用户明确让批量执行，才生成/更新活动标准并恢复剩余串行任务。更新但未获批批量的测试稿保持候选。
4. **自动补人物**：商品、事实和音频齐全但人物缺失时，自动转入内容准备，不问用户选择方法。先写“产品—人群—动作”简报：把真实卖点、目标年龄/问题、日常使用情境和真实动作连起来，再决定人物身份与场景。
5. **人物真实感与适配**：自然皮肤/发丝、不过度磨皮、柔和自然光、环境纹理和轻微生活杂质、中饱和、低对比、普通手机/CCD 抓拍；年龄、性别表达、服装、房间和动作由 SKU 的卖点、人群与场景决定。“每SKU新人”不能退化为随机换脸。
6. **商品保真**：人物底图只负责人物、场景、姿势与可覆盖占位；真实商品作为锁定源层，包装、Logo、文字、颜色、容量、数量和比例不交给模型重画。
7. **白底图拆分判断**：白底图可能是实拍、抠图、修图、渲染或 AI 制作。包装轮廓、Logo、文字、容量、数量和主色用于身份锁定；其光向、色温、阴影、反射和透视不自动视为场景事实。优先让人物姿势和相机视角匹配可用商品视角，只迁移低频场景光；不得扭曲包装和标签迁就错误手势，无法兼顾时索取更合适角度原图。
8. **真实握持与人体工学**：真实商品完全覆盖占位；透视、旋转、比例匹配；拇指/前景手指在前、支撑手指在后。检查肩/肘/前臂/腕/手掌/手指完整链路、可保持关节角、受力点、商品重心和接触阴影。残影、双商品、悬浮、贴片、脱手、复制、形变、穿插、孤立指尖或断腕感直接判废；动作错误时从人物姿势重做，不在错误底图上继续堆蒙版。
9. **图片两级自检**：全图检查卖点、人群、场景、完整肢体链和手机真实感；局部检查包装、占位覆盖、透视、光影、材质、手指前后、接触点、阴影和边缘。图片未过门不得进入 HeyGen。
10. **精确图片批准**：每个SKU只提交一个最终候选；用户批准记录绑定该SKU、最终路径、版本、SHA-256、批准时间和直接证据。批准不跨SKU，也不继承到批准后的压缩、改名、重新合成或其他派生文件；哈希改变即回到图片审核。
11. **远端输入强绑定**：提交前重新计算批准文件哈希，并保存 HeyGen 实际 `remote_avatar_id`/`remote_asset_id`。回读远端缩略图，逐项确认同一人物、同一SKU商品和同一场景；远端ID跨SKU复用、ID缺失、预览不清或不匹配都停止，不依赖页面默认/最近使用项。
12. **视频生成**：默认 720×1280、9:16、25fps、柔和手机感、小幅正面微动作；使用精确锁定音频。严格串行，先写已核验的本地哈希与远端绑定，再创建、轮询、下载。
13. **成片对照检查**：完整解码、音轨与时长、竖屏只是技术门。首条开头/中段/结尾还必须与批准图对照人物身份、精确SKU商品/包装和场景；旧形象、错SKU、灰色占位、贴片、漂移或任一不一致立即判废并冻结批量。
14. **状态回写**：记录方法版本、规则快照、人物 ID、卖点/人群/动作简报、商品源分类与哈希、精确 `presenter_approval`、`remote_input_binding`、`render_match_qc`、光影/透视/人体工学结论、音频哈希、远端 ID、样片批准、验证与停止原因。没有直接批准证据不得写 `user_approved=true`。

## 审核门与自动继续

- 新项目没有批准基准：自动做一个人物候选并本地检查，再做一条视频样片；样片通过后等待用户明确批量指令。
- 当前项目已有同范围批量批准：自动采用最后一次批准的标准，不重复询问，也不要求用户再讲人物、商品、画质等要求。
- 更晚的新测试如果尚未获批批量，只是候选，不覆盖当前标准。
- 用户明确要求“先看所有图片”时，图片审核门覆盖默认单样片顺序。
- 用户未授权的发布、线上修改和额外高成本批量动作不自动执行。

## 停止条件

- 真实商品、事实、审核文案/锁定音频或权利依据缺失；
- 人物与 SKU 不匹配或真实感不通过；
- 卖点、目标人群或真实使用动作缺失，无法形成产品人物简报；
- 白底图光影/透视不可用，且只有扭曲包装才能适配当前人物姿势；
- 肢体链、关节角、握持受力、重心或接触阴影不符合现实人体工学；
- 商品锁定/手部深度/占位覆盖不通过；
- 样片等待用户批准；
- 远端创建状态不明、登录/权限失效或额度不足；
- 多个任务候选无法从状态和摘要唯一裁决；
- 新要求与活动规则发生无法裁决的冲突。

## 禁止回归项

- 找不到知识库后在当前工作目录临时编造流程；
- 创建下划线、空格或日期略有差别的重复任务目录；
- 在商品和音频齐全时问用户选择人物制作路线；
- 先做空手人物、让模型重画真实商品、左上角另贴商品、使用绿色假罐等占位；
- 真实商品浮空、扁平贴片、无透视、手指深度错误或占位残留；
- 把修图/渲染白底图的假光影与假透视直接贴进生活场景；
- 人物只做到“每SKU不同脸”，却没有根据卖点、人群和使用情境选择年龄、形象、环境和动作；
- 在错误动作底图上不断增加手指蒙版，制造穿插、孤立指尖、断腕感或不可能维持的开放手掌姿势；
- 跨 SKU 使用同一张脸；
- 影棚级过度干净、塑料皮肤、强滤镜或默认过锐 1080p；
- 项目已有批准记录仍要求用户重新批准；
- 把一个SKU/一个版本的批准扩大到其他SKU、旧稿或派生文件；
- 状态只写计划使用的本地图片路径，却不保存实际 HeyGen avatar/asset ID 和远端预览证据；
- 沿用页面当前选中、最近使用、Han或任何旧形象，未与批准哈希重新绑定；
- 只检查视频能播放或帧内稳定，不把成片人物、SKU商品和场景与批准图对照；
- 额度不足时裁剪、变速或替换锁定音频，或重复提交远端任务。

## 历史路线与替代关系

2026-08-11 的“真实商品作为参考，人物、手、商品一次生成”曾让测试图通过用户审核，但它无法保证包装像素不被模型重画。2026-08-27 较新的用户批准和34条批次结果验证了“锁定真实商品源层＋正确手部遮挡＋720p柔和输出”。因此前者标记为 `superseded_for_default_product_fidelity`。

2026-09-06 当前5-SKU任务进一步暴露：只锁包装仍不足以保证真实。OCHEAL 的老年人物不匹配年轻碎发整理人群；v2/v3在复杂捏持上补蒙版造成手指穿插和假光影；v4开放手掌腕角不符合人体工学。v5改为约25岁目标人群、肘部放松、前臂自然上抬、腕线同轴、下部侧握，且真实包装锁定，用户明确确认“这张可以”并要求成为以后图片标准。v5外部路径与哈希见2026-09-06来源卡。该批准更新视觉质量门，不授权新的 HeyGen 批量提交；当前批量标准 ID 保持不变并附加本视觉修订。

同日后续批量发生致命回归：本地状态与实际HeyGen人物/商品不一致，旧远端输入又没有精确ID与预览绑定。AI随后两次试图从旧记录还原批准图，均被用户判定错误；这证明旧聊天顺序和AI解释不能替代用户当前提供的精确资产。用户最终直接上传五张正确图并要求除通过图外的生成垃圾全部删除。当前五图已按原字节锁定；旧生成图、35条失效HeyGen视频、成片副本、QA帧和失效执行包已清理。`STD-CNT-PURE-HEYGEN-20260906-01`继续撤销；`CNT-012`负责精确批准与远端绑定，`CNT-013`负责失败媒体即时删除和每SKU单一批准真源。

## 回归用例

| 用例 | 输入状态 | 必须输出 |
|---|---|---|
| R1 外部工作目录启动 | 当前目录不在知识库 | 找到活动 Skill 对应的 `D:\Knowledge` 标记，不声称没有知识库 |
| R2 项目恢复 | 未给路径、仅一个进行中纯 HeyGen 项目 | 恢复该 `ACTIVE_TASK.json`，不创建新目录 |
| R3 近重复路径 | 显式路径不存在但有唯一规范化同名目录 | 报告并采用候选，不创建重复树 |
| R4 缺人物 | 商品、事实、音频齐全，人物缺失 | `prepare_one_presenter_candidate`，不问内部路线 |
| R5 缺商品 | 人物/音频有但真实商品缺失 | `stop_missing_product`，列缺口 |
| R6 样片未批准 | 人物合格、无批准记录 | 只生成一条样片并等待审核 |
| R7 仅样片已批准 | 样片通过但没有批量指令 | `await_batch_approval`，不擅自提交第二条 |
| R8 额度不足 | 项目状态为额度阻断 | `blocked_external_quota`，不提交、不改音频 |
| R9 最新标准选择 | 旧版本获批批量，更新测试稿未获批 | 继续使用旧活动标准，更新稿保持候选 |
| R10 标准晋升 | 更新测试稿后来获批批量 | 更新稿成为活动标准，旧版本标记被替代 |
| R11 缺产品人物简报 | 有商品图但缺真实卖点、目标人群或使用场景 | `stop_missing_product_audience_brief`，不随机生成一张新脸 |
| R12 白底图不可信 | 来源为修图/渲染/不确定，未评估光影或透视 | `stop_assess_product_source`；若只能扭曲包装适配则 `stop_request_better_product_angle` |
| R13 非人体工学动作 | 腕线、关节角、受力或接触不成立 | `reject_and_regenerate_pose`，不在错误底图上堆蒙版 |
| R14 光影/材质不匹配 | 主光、色温、反射或接触阴影不成立 | `reject_and_regenerate_lighting`，不以整体模糊掩盖 |
| R15 模型包装进入成品 | 真实包装未锁定、占位未覆盖或使用生成标签 | `reject_product_fidelity`，不得进入 HeyGen |
| R16 批准范围错用 | 一个SKU获批，却把其他SKU、旧稿或派生文件写成已批准 | `stop_approval_sku_mismatch` / `stop_approved_file_mismatch`，回到精确图片审核 |
| R17 远端形象未绑定 | 本地有批准图，但没有实际 remote avatar/asset ID 或预览不一致 | `bind_and_verify_exact_remote_avatar` / `stop_remote_preview_mismatch`，不得提交 |
| R18 远端ID跨SKU复用 | 同一 remote avatar/asset ID 被两个SKU引用 | `stop_cross_sku_remote_avatar_reuse`，冻结批量 |
| R19 成片与批准图不一致 | 视频可播放，但开头/中段/结尾出现错人物、错SKU、旧形象或占位残影 | `reject_remote_input_or_render_mismatch`，不得标记完成或交付 |

这些用例由 `skill/tiktok-content-system/modules/pure-heygen/tests/test_workspace_state.py`、`test_presenter_image_gate.py`、`test_remote_input_gate.py` 和 `辅助/维护/Test-OperationalKnowledge.ps1` 验证。确定性回归验证门禁路由与状态，不替代真实图片的全图/局部人工视觉质检。
