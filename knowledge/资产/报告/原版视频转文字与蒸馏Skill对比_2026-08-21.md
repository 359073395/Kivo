# 原版视频转文字与蒸馏 Skill 对比

## 结论

上一版只读取了网页说明，没有下载原附件，这一点不完整。本次已经实际下载、解压并逐文件检查 `video-transcript.zip` 和 `yizhan-shendeng-v2.zip`。两个原包均通过 Skill 结构验证；视频包中的 Python 脚本语法通过，但不能原样作为当前 Windows/Codex 的便携执行包。

原包保存在：`资源/raw/attachments/大李AI知识库原始Skill/2026-08-21/`。它们是非活动来源证据，不会与当前七个主 Skill 抢触发。根据用户随后确认，活动版视频转文字模块以原包为基线，只修正六项：作者 macOS 路径、固定临时目录、写死中文、缺少画面 OCR、缺少完整性/覆盖率/错字检查、缺少知识库自动归档；原版模型与转写参数、段落合并逻辑和单文件交付保持不变。

## 一、视频转文字到底需要下载什么

原版方案第一次使用需要：

- Python 隔离环境；
- `faster-whisper`；
- `imageio-ffmpeg`，或复用系统已有 FFmpeg；
- 默认 `Systran/faster-whisper-medium` 模型权重，约 1.5 GB。

当前电脑实测：

- `ffmpeg`、`ffprobe` 已存在；
- Codex 自带 Python 当前没有 `faster-whisper`；
- 当前没有 `imageio-ffmpeg`；
- 当前没有 `faster-whisper-medium` 模型缓存。

所以现在还不能直接离线转写。第一次真正转视频时需要下载 Python 包和模型；模型下载一次后可以复用。模型、虚拟环境和临时 WAV 应放在 `D:\Knowledge` 外，最终 Markdown 逐字稿才写入知识库。本轮没有擅自下载 1.5 GB 模型。

## 二、原版 `video-transcript` 与本库规则

| 对比项 | 原版 | 本库采用方式 |
|---|---|---|
| 识别核心 | faster-whisper，CPU int8 | 保留 |
| 默认模型 | medium，约 1.5 GB | 保留为默认建议，可按速度选择 small |
| 音频抽取 | imageio-ffmpeg，16 kHz 单声道 | 优先复用现有 FFmpeg，缺少时再装 imageio-ffmpeg |
| 时间戳 | 起止时间戳 | 保留 |
| 可读性 | 合并 1–3 秒碎片成自然段 | 保留 |
| 输出 | 时间戳正文＋无时间戳全文 | 保留在同一个 Markdown，避免多份重复文件 |
| 隐私 | 本机处理 | 保留，默认禁止上传私有媒体 |
| 环境 | WorkBuddy/Bash 路径为主 | 动态检测 Windows/Codex 环境 |
| 画面内容 | 不处理 | 增加字幕、屏幕文字、操作步骤和纯画面 OCR/描述 |
| 完整性 | 没有系统覆盖率门禁 | 增加总时长对照和开头/中间/结尾抽查 |
| 存储 | 用户工作区 | 最终稿进 Knowledge，模型/WAV/原视频留库外 |

原版实现的具体问题：`merge.py` 写死作者 macOS 文件路径；`transcribe.py` 固定 `/tmp/whisper_work`；环境安装示例主要是 Bash/WorkBuddy；默认语言写死中文；没有视觉信息、完整性/覆盖率/错字门禁与本库回写逻辑。因此原 zip 保持原样留档，活动实现只对这六项打补丁，不再增加其他方法改写。

## 三、原版“一盏神灯”比上一版多出的关键机制

原版是一套 0–7 步长文本工程，不只是 `what they do / how they think`：

1. 文件、可读性、适合度和多文件分流闸门；
2. 可续跑工作区和 `状态.md`；
3. 20–40 块切分、每批 5 块；
4. 框架、原则、案例、反例、术语五路提取；
5. 每块必须回执，漏块最多补一次；
6. 原文支撑、事前预测力、非泛常识三重验证；
7. 通过率异常时只重筛一次，避免无限消耗；
8. 按有效字数限制 Skill 数量，避免同源 Skill 抢触发；
9. description 元信息闸门和双层诱饵盲测；
10. 默认只交付候选包，不自动安装。

这些机制已适配进 `knowledge-distillation/references/long-source-distillation.md`。

## 四、没有原样照搬的部分

- 原版要求长任务使用多 Agent；当前系统只有在用户明确授权时才可使用子任务，因此本库默认顺序执行，得到授权后再并行。
- 原版把小说、新闻、制度、纯事实材料直接停止；本库只停止“生成 Skill”，仍可将它们文字化并保存为事实、案例、合规或参考知识。
- 原版让扫描 PDF 先由用户自己 OCR；本库要求 AI 使用可用工具完成全页 OCR，并把最终文字稿写回知识库。
- 原版 5,000 字以下一律停止；本库只把 5,000 字作为多 Skill 长流程参考线，短而高密度的方法仍可生成一个窄 Skill。
- 原版要求每个产出 Skill 只有 `SKILL.md`；本库允许复杂 Skill 使用 references、scripts 和 assets，符合当前 Codex Skill 规范。

## 五、当前最终分工

- `knowledge-distillation`：总入口，负责文字化、资料/个人技能蒸馏和质量门禁。
- `local-video-transcription.md`：明确本地转录依赖、下载、参数、存储和原包兼容问题。
- `long-source-distillation.md`：承接“一盏神灯”的长文本闸门、五路提取、验证、数量控制和盲测。
- 原始 zip：只作证据，不参与自动触发。
